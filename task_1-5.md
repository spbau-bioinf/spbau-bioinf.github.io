{: .section__title}

Почти любая обработка данных сводится к вычислениям: длина последовательности в кодонах, число планшетов для партии проб, время прогона, объём реактива. Главная мысль этой страницы: порядок вычислений задают правила приоритета, а не порядок чтения. Если ошибиться в порядке, Python не сообщит об ошибке — он честно посчитает не то (семантическая ошибка, task 1-0).

<section class="subsection" id="s1" markdown="1">

## <span class="subsection__num">1.</span> Как выражение превращается в значение
{: .subsection__title}

<div class="definition" markdown="1">

<span class="definition__term">Выражение</span> — запись из значений, имён и знаков операций, которую Python вычисляет. Результат вычисления выражения — **всегда одно значение**.

</div>

<div class="definition" markdown="1">

<span class="definition__term">Операнды</span> — значения, над которыми выполняется действие. <span class="definition__term">Операторы</span> — знаки, обозначающие действие: `+`, `*` и другие.

</div>

Выражение сворачивается в значение шаг за шагом: на каждом шаге выполняется одна операция, и её операнды заменяются результатом. Какая операция выполняется первой, определяют правила приоритета (раздел 5).

<ol aria-label="Вычисление выражения 2 + 3 * 4" class="flow">
<li class="flow__step"><span class="flow__title">2 + 3 * 4</span><span class="flow__text">операнды 2, 3, 4; операторы + и *</span></li>
<li class="flow__step"><span class="flow__title">2 + 12</span><span class="flow__text">умножение выполняется первым</span></li>
<li class="flow__step"><span class="flow__title">14</span><span class="flow__text">одно значение</span></li>
</ol>

<article class="example" markdown="1">

### Пример 1. Скобки меняют порядок
{: .example__title}

Файл `expressions.py`:

```python
print(2 + 3 * 4)
print((2 + 3) * 4)
```

```text
14
20
```
{: .output}

<div class="analysis" markdown="1">

Разбор
{: .analysis__title}

- Строка 1: умножение имеет более высокий приоритет, чем сложение: 3 \* 4 = 12, затем 2 + 12 = 14.
- Строка 2: скобки вычисляются первыми: 2 + 3 = 5, затем 5 \* 4 = 20.
- Скобки нужны, когда вы хотите другой порядок, — или когда хотите, чтобы порядок был очевиден читателю.

</div>

</article>

## <span class="subsection__num">2.</span> Семь арифметических операторов
{: .subsection__title}

| Оператор | Действие | Пример | Результат |
|---|---|---|---|
| `x + y` | сложение | `30 + 12` | `42` |
| `x - y` | вычитание | `43 - 1` | `42` |
| `x * y` | умножение | `6 * 7` | `42` |
| `x / y` | деление | `84 / 2` | `42.0` |
| `x // y` | целочисленное деление: деление без дробной части | `85 // 2` | `42` |
| `x % y` | остаток от деления | `7 % 3` | `1` |
| `x ** y` | возведение в степень | `7 ** 2` | `49` |

Знак минус перед числом или именем (`-x`) — <dfn>унарный минус</dfn>: он меняет знак значения. Вокруг бинарных операторов по PEP 8 ставят пробелы (task 1-1).

<article class="example" markdown="1">

### Пример 2. Все семь операторов
{: .example__title}

Файл `operators.py`:

```python
print(30 + 12)
print(43 - 1)
print(6 * 7)
print(84 / 2)
print(85 // 2)
print(7 % 3)
print(7 ** 2)
```

```text
42
42
42
42.0
42
1
49
```
{: .output}

<div class="analysis" markdown="1">

Разбор
{: .analysis__title}

- Строка 4: результат `/` — вещественное число, даже при делении нацело.
- Строка 5: 85 / 2 = 42,5; целочисленное деление отбрасывает дробную часть и даёт целое 42.
- Строка 6: 7 = 3 · 2 + 1, остаток 1.
- Строка 7: `**` — два знака умножения подряд, без пробела между ними.

</div>

</article>

<div class="mistake" markdown="1">

Типичная ошибка: `^` вместо `**`
{: .mistake__title}

Файл `power.py`:

```python
print(2 ^ 3)
```
{: .code-block--bad}

```text
1
```
{: .output}

```python
print(2 ** 3)
```
{: .code-block--good}

```text
8
```
{: .output}

Во многих программах (например, в электронных таблицах) степень обозначают знаком `^`. В Python этот знак означает совсем другую, побитовую операцию, поэтому программа молча выдаёт 1. Это семантическая ошибка: сообщения нет. Степень в Python — только `**`.

</div>

</section>

## <span class="subsection__num">3.</span> Деление: `/`, `//` и `%`
{: .subsection__title}

### Оператор `/` больше не «делит нацело»
{: .block-title}

В Python 2 деление двух целых чисел отбрасывало дробную часть: `59 / 60` давало `0`. В Python 3 это изменили: `/` — всегда обычное деление с вещественным результатом, а для деления нацело есть отдельный оператор `//`. В старых книгах и на старых сайтах можно встретить код, который в Python 3 работает иначе.

<article class="example" markdown="1">

### Пример 3. Два вида деления
{: .example__title}

Файл `division.py`:

```python
minute = 59
print(minute / 60)
print(minute // 60)
print(60 / 60)
print(type(60 / 60))
```

```text
0.9833333333333333
0
1.0
<class 'float'>
```
{: .output}

<div class="analysis" markdown="1">

Разбор
{: .analysis__title}

- Строка 2: 59 минут — это 0,98(3) часа; бесконечная дробь показана с конечным числом цифр.
- Строка 3: сколько *полных* часов в 59 минутах — ноль.
- Строки 4–5: даже 60 / 60 даёт `1.0` типа `float`.

</div>

</article>

### `//` и `%` — пара
{: .block-title}

<div class="definition" markdown="1">

Для целых `x` и `y` (`y` ≠ 0) всегда выполняется равенство: `(x // y) * y + x % y == x`. Целая часть от деления и остаток вместе восстанавливают исходное число.

</div>

- `x // y` отвечает на вопрос «сколько целых `y` помещается в `x`»: сколько полных часов в минутах, полных кодонов в последовательности, полных планшетов в партии.
- `x % y` отвечает на вопрос «сколько осталось»: оставшиеся минуты, нуклеотиды, пробы.
- `x % y == 0` — проверка того, что `x` делится на `y` нацело; результат — `True` или `False`.
- Делить на ноль нельзя и здесь: `10 // 0` и `10 % 0` вызывают `ZeroDivisionError`. Текст сообщения зависит от версии: в Python 3.11–3.13 — `integer division or modulo by zero` или `integer modulo by zero`, в Python 3.14 — `division by zero`.

<article class="example" markdown="1">

### Пример 4. Минуты в часы и минуты
{: .example__title}

Файл `minutes.py`:

```python
minutes = 105
hours = minutes // 60
rest = minutes % 60
print(hours)
print(rest)
print(60 * hours + rest)
```

```text
1
45
105
```
{: .output}

<div class="analysis" markdown="1">

Разбор
{: .analysis__title}

| Строка | Вычисление | minutes | hours | rest | Вывод |
|---|---|---|---|---|---|
| 1 | — | 105 | — | — | — |
| 2 | 105 // 60 → 1 | 105 | 1 | — | — |
| 3 | 105 % 60 → 45 | 105 | 1 | 45 | — |
| 4 | — | 105 | 1 | 45 | 1 |
| 5 | — | 105 | 1 | 45 | 45 |
| 6 | 60 \* 1 + 45 → 105 | 105 | 1 | 45 | 105 |
{: .data-table--trace}

105 минут — это 1 час 45 минут. Строка 6 проверяет пару: 60 · 1 + 45 = 105 — исходное число восстановлено.

</div>

</article>

<article class="example" markdown="1">

### Пример 5. Полные кодоны
{: .example__title}

Сколько полных кодонов в последовательности и сколько нуклеотидов останется в конце — на оба вопроса отвечают две операции. Файл `codons.py`:

```python
sequence = 'ATGGCCATTGTAATGGGCTG'
length = len(sequence)
print(length)
print(length // 3)
print(length % 3)
print(length % 3 == 0)
```

```text
20
6
2
False
```
{: .output}

<div class="analysis" markdown="1">

Разбор
{: .analysis__title}

- Длина последовательности — 20 нуклеотидов.
- `20 // 3` = 6 полных кодонов; `20 % 3` = 2 нуклеотида остаются в конце.
- `20 % 3 == 0` — ложь: длина не кратна трём, последовательность не делится на кодоны без остатка.

</div>

</article>

### Особенность: отрицательные числа
{: .block-title}

`x // y` округляет результат деления **вниз**, к меньшему целому, а не просто отбрасывает дробную часть. Для положительных чисел это одно и то же, для отрицательных — нет. Остаток при этом имеет тот же знак, что и делитель, так что равенство пары по-прежнему выполняется.

<article class="example" markdown="1">

### Пример 6. Деление отрицательного числа
{: .example__title}

Файл `negative.py`:

```python
print(7 // 2)
print(-7 // 2)
print(7 % 2)
print(-7 % 2)
print(-7 // 2 * 2 + -7 % 2)
```

```text
3
-4
1
1
-7
```
{: .output}

<div class="analysis" markdown="1">

Разбор
{: .analysis__title}

- −7 / 2 = −3,5. Округление вниз даёт −4, а не −3. Сравните с `int(-3.5)`, который отбрасывает дробную часть и даёт −3 (task 1-4).
- Остаток: −7 − (−4 · 2) = −7 + 8 = 1. Он неотрицателен, потому что делитель 2 положителен.
- Строка 5 проверяет пару: (−4) · 2 + 1 = −7.
- Это свойство удобно для кольцевых координат: позиция на кольцевой плазмиде после сдвига назад всё равно получается в пределах от 0 до длины плазмиды: при длине 2686 сдвиг от позиции 50 на 100 назад даёт `(50 - 100) % 2686` = 2636.

</div>

</article>

<section class="subsection" id="s4" markdown="1">

## <span class="subsection__num">4.</span> Тип результата: правило «заражения»
{: .subsection__title}

<div class="definition" markdown="1">

<span class="definition__term">Правило «заражения».</span> Если хотя бы один операнд арифметической операции — `float`, результат тоже `float`. Если оба операнда — `int`, результат `int` для `+`, `-`, `*`, `//`, `%` и для `**` с неотрицательной степенью.

</div>

Исключения из «целого» результата при целых операндах: деление `/` всегда даёт `float`; возведение в отрицательную степень тоже даёт `float` (`2 ** -1` → `0.5`).

<article class="example" markdown="1">

### Пример 7. Один `float` — и весь результат вещественный
{: .example__title}

Файл `float_rule.py`:

```python
print(4 / 2)
print(1 + 2.0)
print(3.0 ** 2)
print(7 // 2.0)
print(7 % 2.5)
print(2 ** -1)
print(type(2 ** 3))
```

```text
2.0
3.0
9.0
3.0
2.0
0.5
<class 'int'>
```
{: .output}

<div class="analysis" markdown="1">

Разбор
{: .analysis__title}

- Строки 2–3: один вещественный операнд делает результат вещественным, хотя значение целое.
- Строка 4: целочисленное деление с вещественным операндом тоже даёт `float`: `3.0`, а не `3`.
- Строка 5: остаток работает и для вещественных чисел: 7 = 2,5 · 2 + 2.
- Строка 7: оба операнда целые, степень неотрицательная — результат `int`.
- Практическое следствие: длина последовательности, число кодонов и число проб — всегда целые. Если такая величина вдруг получилась с точкой, значит, где-то в расчёте затесалось деление `/` вместо `//` или вещественный операнд.

</div>

</article>

## <span class="subsection__num">5.</span> Кто считается первым: приоритет операций
{: .subsection__title}

| Приоритет | Операции | Порядок при равном приоритете |
|---|---|---|
| 1 (высший) | `( )` — скобки | изнутри наружу |
| 2 | `**` — степень | **справа налево**: `2 ** 3 ** 2` = 2<sup>9</sup> |
| 3 | унарный минус: `-x` | — |
| 4 | `*`, `/`, `//`, `%` | слева направо |
| 5 | `+`, `-` | слева направо |
| 6 (низший) | сравнения: `==`, `!=`, `<`, `>`, `<=`, `>=` | — |

Сравнения выполняются после арифметики, поэтому `length % 3 == 0` означает «(остаток) равен нулю» без дополнительных скобок.

<article class="example" markdown="1">

### Пример 8. Ловушки приоритета
{: .example__title}

Файл `precedence.py`:

```python
print(2 ** 1 + 1)
print(2 * 3 - 1)
print(5 - 3 - 1)
print(20 / 10 / 2)
print(2 ** 3 ** 2)
print(-3 ** 2)
print((-3) ** 2)
```

```text
3
5
1
1.0
512
-9
9
```
{: .output}

<div class="analysis" markdown="1">

Разбор
{: .analysis__title}

| Выражение | Кажется | На самом деле | Почему |
|---|---|---|---|
| `2 ** 1 + 1` | 2<sup>2</sup> = 4 | (2<sup>1</sup>) + 1 = 3 | степень выше сложения |
| `2 * 3 - 1` | 2 · 2 = 4 | (2 · 3) − 1 = 5 | умножение выше вычитания |
| `5 - 3 - 1` | 5 − 2 = 3 | (5 − 3) − 1 = 1 | при равном приоритете — слева направо |
| `20 / 10 / 2` | 20 / 5 = 4.0 | (20 / 10) / 2 = 1.0 | слева направо |
| `2 ** 3 ** 2` | 8<sup>2</sup> = 64 | 2<sup>9</sup> = 512 | степень — справа налево |
| `-3 ** 2` | (−3)<sup>2</sup> = 9 | −(3<sup>2</sup>) = −9 | степень выше унарного минуса |

</div>

</article>

<aside class="callout callout--hint" markdown="1">

Задумались о приоритете дольше секунды — ставьте скобки
{: .callout__title}

Лишние скобки не замедляют программу и не считаются ошибкой, а читателю сразу ясен порядок: `(2 ** 3) ** 2`, `-(3 ** 2)`.

</aside>

### Формула из условия → выражение Python
{: .block-title}

1. Запишите знаки операций: умножение — `*` (точку и крестик не пишут, знак умножения не пропускают: 2*x* → `2 * x`), деление — `/` или `//`, степень — `**`.
1. Числитель и знаменатель дроби, содержащие сложение или вычитание, возьмите в скобки: <sup>a + b</sup>⁄<sub>c</sub> → `(a + b) / c`.
1. Проверьте выражение на простых числах, для которых ответ известен заранее.
{: .steps}

<article class="example" markdown="1">

### Пример 9. Средняя длина прочтения
{: .example__title}

Три прочтения имеют длины 148, 150 и 155 нуклеотидов. Средняя длина = (сумма длин) / 3. Файл `mean_length.py`:

```python
print(148 + 150 + 155 / 3)
```
{: .code-block--bad}

```text
349.6666666666667
```
{: .output}

```python
print((148 + 150 + 155) / 3)
```
{: .code-block--good}

```text
151.0
```
{: .output}

<div class="analysis" markdown="1">

Разбор
{: .analysis__title}

- Без скобок на 3 делится только 155, и к результату прибавляются две другие длины. Средняя длина прочтения не может быть больше самого длинного из них — это сразу выдаёт семантическую ошибку.
- Со скобками сначала вычисляется сумма 453, затем 453 / 3 = 151.0.

</div>

</article>

## Итоговое задание: план загрузки планшетов <span class="level level--5">Уровень 5 · итоговое</span>

Файл: <span class="task__file">task\_1-5\_plates.py</span>
{: .task__meta}

Партию проб нужно разложить по 96-луночным планшетам для ПЦР. Напишите программу, которая рассчитывает план загрузки.

**Исходные данные:**

- проб в партии — 250;
- лунок в планшете — 96, из них 2 в каждом планшете занимают контрольные образцы;
- один прогон планшета длится 95 минут; планшеты прогоняются по очереди;
- на одну пробу нужно 12,5 мкл реакционной смеси; смесь готовят с запасом 10 %, то есть общий объём умножают на 11 / 10;
- число планшетов с округлением вверх для *n* проб и *k* рабочих лунок в планшете: (*n* + *k* − 1) // *k*.

Программа выводит только числа, по одному в строке, в таком порядке: рабочих лунок в планшете; полностью заполненных планшетов; проб в последнем, неполном планшете; всего планшетов; время всех прогонов — полных часов; время всех прогонов — оставшихся минут; объём смеси с запасом, мкл.

```text
94
2
62
3
4
45
3437.5
```
{: .output data-label="Требуемый вывод"}

**Требования:**

1. Исходные данные привязаны к переменным с понятными именами; промежуточные результаты, которые используются несколько раз, тоже привязаны к переменным.
1. Все числа вывода получаются вычислением; готовых результатов в программе нет.
1. Запас смеси учитывается именно умножением на `11 / 10`, в указанном порядке: число проб × объём на пробу × 11 / 10. В комментарии в конце файла запишите, что выводит выражение, где вместо `11 / 10` стоит `1.1`, — этот результат объясняется в [task 1-6](task_1-6.html).
