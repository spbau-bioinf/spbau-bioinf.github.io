<section class="theory" markdown="1">

## Теоретические сведения
{: .section__title}

Устанавливая Python, вы получаете не только язык. Вместе с интерпретатором приходит большая стандартная библиотека — сотни готовых модулей. Ещё сотни тысяч пакетов, созданных сообществом, можно установить дополнительно. Всё это вместе называют <dfn>экосистемой Python</dfn>.

Именно экосистема сделала Python одним из основных языков биоинформатики: для разбора форматов последовательностей, запросов к биологическим базам данных, табличного анализа, численных расчётов и научных графиков есть готовые инструменты. Понимать устройство экосистемы нужно по двум причинам: чтобы отличать ошибку в своём коде от проблемы окружения и чтобы писать код, который легко читают другие люди.

</section>

## <span class="subsection__num">1.</span> Три слоя «Python»
{: .subsection__title}

То, что называют словом «Python», состоит из трёх слоёв.

| Слой | Что входит | Установка | Нужен ли `import` |
|---|---|---|---|
| **Ядро языка** | правила записи программ; встроенные типы данных (числа, строки, списки, множества, словари); встроенные функции — `print()`, `len()`, `type()` и другие | вместе с интерпретатором | нет |
| **Стандартная библиотека** | модули `math`, `sys`, `random`, `os` и сотни других | уже установлена вместе с Python | да |
| **Сторонние пакеты** | `numpy`, `pandas`, `biopython`, `requests` и другие; развиваются отдельно от языка | вручную, из каталога PyPI | да |

<div class="definition" markdown="1">

<span class="definition__term">Модуль</span> — отдельная единица кода (обычно файл с расширением `.py`), содержимое которой можно подключить к своей программе и использовать.

</div>

<div class="definition" markdown="1">

<span class="definition__term">Пакет</span> — набор модулей, который распространяется и устанавливается как единое целое. Сторонние пакеты публикуются в каталоге PyPI.

</div>

<div class="definition" markdown="1">

<span class="definition__term">Библиотека</span> — общее название модуля или пакета, который предоставляет готовые функции для решения задач определённого круга.

</div>

Функции ядра, например `print()`, доступны в любой программе сразу. Содержимое модуля стандартной библиотеки становится доступно только после его подключения, даже если модуль уже установлен.

<article class="example" markdown="1">

### Пример 1. Модуль без подключения
{: .example__title}

Модуль `math` из стандартной библиотеки содержит математические функции, например `math.sqrt()` — квадратный корень. Попробуем обратиться к нему без подключения. Файл `no_import.py`:

```python
print('Корень из 16:')
print(math.sqrt(16))
```
{: .code-block--bad}

```text
Корень из 16:
Traceback (most recent call last):
  File "C:\Users\student\Desktop\python_work\no_import.py", line 2, in <module>
    print(math.sqrt(16))
          ^^^^
NameError: name 'math' is not defined. Did you forget to import 'math'?
```
{: .output .output--error data-label="Вывод терминала (Python 3.12 и новее)"}

<div class="analysis" markdown="1">

Разбор
{: .analysis__title}

- Строка 1 выполнилась: `print()` — функция ядра, подключать её не нужно.
- В строке 2 Python не знает имени `math`: модуль установлен, но программа его не подключила. Возникает ошибка времени выполнения `NameError` (task 1-0).
- Начиная с Python 3.12 интерпретатор подсказывает: `Did you forget to import 'math'?` — «Вы не забыли подключить math?». В Python 3.11 последняя строка сообщения заканчивается словами `is not defined`, без подсказки.
- Как подключить модуль, разобрано в разделе 2.

</div>

</article>

<section class="subsection" id="s2" markdown="1">

## <span class="subsection__num">2.</span> Подключение модуля: `import`
{: .subsection__title}

<div class="overview" markdown="1">

Обзорно
{: .overview__label}

Здесь показано только базовое подключение модулей стандартной библиотеки. Подробно механизм `import` изучается в теме 11 «Модули, пакеты и интерфейс командной строки».
{: .overview__ref}

### Две формы подключения
{: .block-title}

<div class="syntax">import имя_модуля<br/>имя_модуля.имя</div>

Команда `import` находит модуль и загружает его. После этого содержимое модуля доступно через точку: сначала имя модуля, затем имя того, что в нём лежит.

<div class="syntax">from имя_модуля import имя<br/>имя</div>

Вторая форма берёт из модуля только одно имя, и дальше его можно писать без имени модуля и точки.

### Что понадобится в этой работе
{: .block-title}

| Запись | Что это | Пример результата |
|---|---|---|
| `math.sqrt(x)` | функция: квадратный корень из числа `x`; результат — вещественное число | `math.sqrt(16)` → `4.0` |
| `math.pi` | значение: число π; это не функция, скобки после него не ставятся | `3.141592653589793` |
| `sys.version` | значение: текст с версией интерпретатора и сведениями о его сборке | зависит от системы |

### Правила
{: .block-title}

- Команды `import` пишут в начале файла, каждый модуль — на отдельной строке.
- Подключение действует до конца программы: один раз подключили — пользуетесь во всех следующих строках.
- Имя модуля пишется точно: `math`, а не `Math` и не `maths`.

</div>

<article class="example" markdown="1">

### Пример 2. Модуль `math`
{: .example__title}

Исправленная версия примера 1. Файл `with_import.py`:

```python
import math

print('Корень из 16:')
print(math.sqrt(16))
print('Число пи:')
print(math.pi)
```

```text
Корень из 16:
4.0
Число пи:
3.141592653589793
```
{: .output}

<div class="analysis" markdown="1">

Разбор
{: .analysis__title}

- Строка 1: `import math` находит модуль `math` в стандартной библиотеке и подключает его. На экран эта строка ничего не выводит.
- Строка 2 пустая: PEP 8 советует отделять подключения от остального кода (раздел 5).
- Строка 4: сначала вычисляется `math.sqrt(16)`, получается `4.0`, затем `print()` выводит это значение. Результат вещественный — с точкой, — хотя корень из 16 целый: функция `math.sqrt()` всегда возвращает вещественное число.
- Строка 6: `math.pi` записано без скобок, потому что это готовое значение, а не действие. Выведено 16 значащих цифр — столько помещается в вещественное число Python (подробно — в [task 1-6](task_1-6.html)).

</div>

</article>

<article class="example" markdown="1">

### Пример 3. Форма `from … import …`
{: .example__title}

Файл `from_import.py`:

```python
from math import sqrt

print('Корень из 6.25:')
print(sqrt(6.25))
```

```text
Корень из 6.25:
2.5
```
{: .output}

<div class="analysis" markdown="1">

Разбор
{: .analysis__title}

- Строка 1 берёт из модуля `math` одно имя — `sqrt`.
- В строке 4 функция вызывается просто как `sqrt()`, без `math.` в начале. Запись `math.sqrt()` здесь, наоборот, вызвала бы `NameError`: имя `math` этой программе не известно.
- В программах курса используйте первую форму, `import math`: по записи `math.sqrt` сразу видно, откуда взята функция.

</div>

</article>

<article class="example" markdown="1">

### Пример 4. Модуль не найден
{: .example__title}

В имени модуля опечатка. Файл `typo_module.py`:

```python
import maths

print('Модуль подключён')
```
{: .code-block--bad}

```text
Traceback (most recent call last):
  File "C:\Users\student\Desktop\python_work\typo_module.py", line 1, in <module>
    import maths
ModuleNotFoundError: No module named 'maths'
```
{: .output .output--error}

<div class="analysis" markdown="1">

Разбор
{: .analysis__title}

- Разбор файла прошёл успешно: команда записана по правилам. Ошибка возникла при выполнении строки 1, когда Python стал искать модуль `maths` и не нашёл его. Строка 3 уже не выполнилась.
- `ModuleNotFoundError: No module named 'maths'` — «модуль с именем maths не найден».
- У этой ошибки три типичные причины: опечатка в имени модуля (как здесь); сторонний пакет не установлен; пакет установлен, но для другого интерпретатора Python (раздел 3). Две последние — проблемы **окружения**, а не кода: сам текст программы может быть правильным.

</div>

</article>

<aside class="callout callout--warning" markdown="1">

Не называйте свои файлы именами модулей
{: .callout__title}

Если сохранить свою программу как `math.py`, `random.py` или `this.py`, команда `import` в программах из той же папки может подключить ваш файл вместо модуля стандартной библиотеки. Результат — непонятные ошибки. Правила поиска модулей разбираются в теме 11; пока просто используйте имена файлов из заданий.

</aside>

## <span class="subsection__num">3.</span> Сторонние пакеты: PyPI и `pip`
{: .subsection__title}

<dfn>PyPI</dfn> (Python Package Index, адрес `pypi.org`) — общий каталог сторонних пакетов для Python. <dfn>pip</dfn> — программа, которая скачивает пакеты из PyPI и устанавливает их. Она поставляется вместе с Python.

### Команды pip
{: .block-title}

Команды pip вводятся **в терминале**, а не в интерактивном режиме Python и не в файле программы.

| Действие | Windows | macOS, Linux |
|---|---|---|
| версия pip и то, к какому Python он относится | `python -m pip --version` | `python3 -m pip --version` |
| список установленных пакетов | `python -m pip list` | `python3 -m pip list` |
| установить пакет | `python -m pip install имя_пакета` | `python3 -m pip install имя_пакета` |

В Windows вместо `python` можно писать `py`, например `py -m pip list`.

<div class="definition" markdown="1">

<span class="definition__term">Зачем писать `-m pip`.</span> Запись `python -m pip` означает: «запусти модуль pip того самого интерпретатора, который вызывается командой `python`». На одном компьютере может быть установлено несколько версий Python, и у каждой — свой набор пакетов. Команда `pip` без `python -m` может относиться к другой версии. Тогда пакет установится «не туда», и программа выдаст `ModuleNotFoundError`, хотя установка прошла успешно.

</div>

<article class="example" markdown="1">

### Пример 5. Какой pip у вас установлен
{: .example__title}

```text
python3 -m pip --version
```
{: data-label="Терминал (Linux)"}

```text
pip 24.0 from /usr/lib/python3/dist-packages/pip (python 3.12)
```
{: .output data-label="Вывод терминала (пример; у вас будет свой)"}

<div class="analysis" markdown="1">

Разбор
{: .analysis__title}

- `pip 24.0` — версия самой программы pip.
- `from /usr/lib/python3/dist-packages/pip` — папка, где лежит pip. В Windows путь будет вида `C:\Users\…\Python312\Lib\site-packages\pip`.
- `(python 3.12)` — версия Python, к которой относится этот pip. Пакеты, установленные этой командой, будут доступны именно программам, запущенным этой версией.

</div>

</article>

<div class="mistake" markdown="1">

Типичная ошибка: команда pip в интерактивном режиме
{: .mistake__title}

```text
>>> @@pip install numpy@@
  File "<stdin>", line 1
    pip install numpy
        ^^^^^^^
SyntaxError: invalid syntax
```
{: .output .output--error data-label="Интерактивный режим — неверно (Python 3.11–3.12)"}

```python
python -m pip install numpy
```
{: .code-block--good data-label="Верно: выйти из интерактивного режима и ввести в терминале"}

`pip install numpy` — команда для терминала, а не текст на Python. Интерпретатор пытается прочитать её как программу на Python и сообщает о синтаксической ошибке. В Python 3.13 и новее сообщение то же, только вместо `<stdin>` указано `<python-input-0>`. Если перед строкой стоит `>>>`, вы в интерактивном режиме: сначала выйдите из него командой `quit()`.

</div>

<aside class="callout callout--important" markdown="1">

В первом семестре устанавливать пакеты не нужно
{: .callout__title}

Все задания первого семестра решаются средствами ядра языка и стандартной библиотеки. Сторонние пакеты понадобятся во втором семестре, и устанавливать их будем в отдельное <dfn>виртуальное окружение</dfn> (тема 11). Это защита системы, а не ошибка в вашей команде: решение — то же виртуальное окружение.

</aside>

<section class="subsection" id="s5" markdown="1">

## <span class="subsection__num">5.</span> Читаемость кода и PEP 8
{: .subsection__title}

<div class="overview" markdown="1">

Обзорно
{: .overview__label}

Здесь приведены только базовые правила оформления, нужные уже сейчас. Подробно стиль кода, автоформатирование и проверка кода изучаются в теме 10 «Качество кода, тестирование и коллективная разработка».
{: .overview__ref}

Код читают гораздо чаще, чем пишут: при отладке, доработке, проверке преподавателем или коллегой. Поэтому нужен общий стиль, а не личный вкус каждого. Для Python такой стиль описан в документе <dfn>PEP 8</dfn>. PEP (Python Enhancement Proposal) — документ, в котором сообщество описывает предложения и соглашения о развитии Python; PEP 8 — соглашение об оформлении кода.

PEP 8 — правила для людей, а не для интерпретатора: программа, оформленная не по PEP 8, выполнится так же. Но её труднее читать, а значит, в ней труднее искать ошибки. Поскольку правила чёткие, их можно проверять и применять автоматически: для этого есть программы-<dfn>линтеры</dfn> (например, pylint) и <dfn>автоформатеры</dfn> (например, black). С ними вы познакомитесь в теме 10.

### Базовые правила
{: .block-title}

| Правило | Так | Не так |
|---|---|---|
| подключения — в начале файла, по одному модулю в строке | `import math`<br>`import sys` | `import math, sys` в середине файла |
| между именем функции и скобкой пробела нет | `print('Готово')` | `print ('Готово')` |
| сразу внутри скобок пробелов нет | `math.sqrt(2)` | `math.sqrt( 2 )` |
| вокруг знаков действий — пробелы | `20 + 180` | `20+180` |
| после `#` — пробел; комментарий в конце строки отделяется от кода двумя пробелами | `print(5)  # число проб` | `print(5)#число проб` |
| длина строки — не более 79 символов | длинное выражение или комментарий переносится на отдельную строку | строка, уходящая за край экрана |
| отступ — 4 пробела на уровень | настраивается в редакторе (task 1-2); понадобится с темы 3 | табуляция или 2 пробела |
| имена — строчными буквами через подчёркивание | `gc_content` | `GCcontent`, `gccontent` |

PEP 8 разрешает не ставить пробелы вокруг действий с более высоким приоритетом, например `2 + 3*4`. В нашем курсе для единообразия ставьте пробелы вокруг всех знаков действий: `2 + 3 * 4`. Об именах переменных — в task 1-3.
{: .muted}

</div>

{: .example__title}

В Python встроен короткий текст о принципах языка — «Дзен Python» (документ PEP 20). Чтобы его увидеть, достаточно подключить модуль `this`. Файл `zen.py`:

### Пример 8. Одна программа — два оформления
{: .example__title}

Файл `volume_bad.py`:

```python
print ( 'Проба и буфер, мкл:' )
print(20+180)#сумма объёмов
```
{: .code-block--bad data-label="Неверно (оформление)"}

```text
Проба и буфер, мкл:
200
```
{: .output}

Файл `volume_good.py`:

```python
print('Проба и буфер, мкл:')
print(20 + 180)  # сумма объёмов
```
{: .code-block--good}

```text
Проба и буфер, мкл:
200
```
{: .output}

<div class="analysis" markdown="1">

Разбор
{: .analysis__title}

- Обе программы выводят одно и то же: для интерпретатора эти лишние и недостающие пробелы ничего не меняют.
- В первой программе нарушены четыре правила: пробел между `print` и скобкой; пробелы сразу внутри скобок; нет пробелов вокруг `+`; комментарий прижат к коду, и после `#` нет пробела.
- Вторая программа читается быстрее: глаз сразу отделяет имя функции, выражение и комментарий.

А как же имена наших файлов?

Имена учебных файлов вида `task_1-3_1.py` содержат дефис — так в курсе нумеруются задания. Такие файлы можно запускать, но нельзя подключить к другой программе командой `import`: для Python дефис — знак вычитания.
