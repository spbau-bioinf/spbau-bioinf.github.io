# Практические занятия · Язык программирования Python

Сайт собирается GitHub Pages (Jekyll) из Markdown-файлов этой папки.
Правите `.md` → Commit → Push → через 1–2 минуты сайт обновлён.

## Что где лежит

| Путь | Что это |
|---|---|
| `task_1.md`, `task_1-0.md` … | страницы занятия — **их и правим** |
| `_data/nav.yml` | меню: порядок страниц, их коды и названия |
| `_config.yml` | название курса, подпись автора, подвал |
| `_layouts/default.html` | общий шаблон: меню, шапка, подвал, кнопки «Предыдущая / Следующая» |
| `_includes/toc.html` | оглавление на странице `task_1` (строится из меню) |
| `assets/css/style.css` | ваши исходные стили, без изменений |
| `assets/css/markdown.css` | стили для блоков, которые строятся из Markdown |
| `index.md` | главная страница со списком занятий |
| `tools/html2md.py` | конвертер HTML → Markdown для следующих занятий |

Меню, шапку, подвал, подпись автора и кнопки перехода писать в страницах
**не нужно** — шаблон добавляет их сам. Кнопки считаются по порядку в `_data/nav.yml`.

## Начало страницы

```yaml
---
work: 1                # номер занятия (из _data/nav.yml)
code: "task 1-3"       # код страницы
title: "Переменные, объекты, ссылочная модель"   # заголовок в шапке
---
```

Необязательные поля: `kicker` (строка над заголовком, по умолчанию
«Практическое занятие #1 · task 1-3»), `head_title` (заголовок вкладки браузера),
`show_author: false` (скрыть подпись автора).

## Шпаргалка по разметке

**Обычный текст** — как в любом Markdown: `**жирный**`, `*курсив*`,
`` `код` ``, `[ссылка](task_1-4.html)`, списки `-` и `1.`, таблицы `| a | b |`.
Спецсимволы `_ * [ ] |` в обычном тексте пишутся с `\`: `task\_1-3\_1.py`
(внутри `` `кода` `` — без `\`).

**Класс для абзаца, заголовка, списка** — строкой сразу под ним:

```markdown
Разбор
{: .analysis__title}
```

**Блоки-обёртки** (теория, пример, задание, выноска…) — HTML-тег с `markdown="1"`.
Пустые строки после открывающего и перед закрывающим тегом обязательны,
текст внутри **без отступов**:

```markdown
<article class="task" id="task-1" markdown="1">

### Задание 1. Счётчик прочтений <span class="level level--1">Уровень 1</span>
{: .task__title}

Файл: <span class="task__file">task_1-3_1.py</span>
{: .task__meta}

Текст задания.

</article>
```

Классы обёрток: `theory`, `goal`, `callout callout--hint|--warning|--important`,
`subsection`, `example`, `analysis`, `definition`, `task`, `task task--star`,
`final-task`, `capstone`, `overview`, `mistake`, `compare`, `then`.

**Код** — подпись «Код» ставится сама:

````markdown
```python
print(type(17))
```
````

Неверный / верный вариант и своя подпись:

````markdown
```python
print(gc_percent)
```
{: .code-block--bad}

```python
print('ok')
```
{: .code-block--good data-label="Полезный комментарий"}
````

**Вывод терминала** — подпись «Вывод терминала» ставится сама;
текст между `@@` выделяется как ввод пользователя:

````markdown
```text
What is your name?
@@Anna@@
Hello, Anna
```
{: .output}
````

Варианты: `{: .output .output--error}` (ошибка),
`{: .output .output--file}` (содержимое файла),
`{: .output data-label="Требуемый вывод"}` (своя подпись).

**Дерево папок** — `@@…@@` выделяет новую папку:

````markdown
```text
ivanov_ii/
└── projects_1/
    └── @@task_1_3/@@
```
{: .folder-tree}
````

**Схемы, блоки синтаксиса, сложные таблицы** остаются обычным HTML прямо
в `.md`-файле (`<figure class="diagram">…`, `<div class="syntax">…</div>`) —
Jekyll выводит его как есть.

## Как добавить страницу

1. Создайте `task_1-10.md` с «шапкой» из полей выше.
2. Добавьте её в `_data/nav.yml` в нужное место списка `pages`.
   Меню, оглавление и кнопки перехода обновятся сами.

## Как перенести следующее занятие из HTML

HTML-файлы держите **вне** этой папки (иначе `task_2.html` и `task_2.md`
будут спорить за один адрес). Затем в корне сайта:

```
pip install beautifulsoup4 lxml
python tools/html2md.py путь/к/папке_с_html
```

Скрипт создаст `task_2*.md` и добавит занятие в `_data/nav.yml`.
Он печатает, какие блоки оставил в HTML (обычно сложные таблицы) — это нормально.

## Просмотр на своём компьютере (необязательно)

Нужен Ruby (на Windows — RubyInstaller с DevKit). Один раз:

```
gem install bundler
bundle install
```

Затем при каждой работе:

```
bundle exec jekyll serve
```

Сайт откроется по адресу http://localhost:4000 и будет обновляться
при сохранении файлов (кроме `_config.yml` — после него перезапустите команду).
