<section class="theory" markdown="1">

## Теоретические сведения
{: .section__title}

В task 1-5 вы видели результаты вроде `5.208333333333333` и `3437.5000000000005`. Длинные «хвосты» в вещественных числах — не поломка компьютера и не ошибка Python. Так устроен формат, в котором компьютер хранит дробные числа: он конечен, и большинство десятичных дробей в нём можно записать только приближённо.

Для биоинформатики это не абстракция: GC-состав, концентрации, оценки качества — вещественные числа. Если сравнивать их через `==`, программа будет ошибаться незаметно. Эта страница — вторая часть темы «Арифметические операции, особенности вещественной арифметики и точность вычислений»: почему так происходит и какими тремя инструментами пользоваться вместо равенства.

</section>

## <span class="subsection__num">1.</span> `float` — это конечный формат
{: .subsection__title}

<div class="definition" markdown="1">

Значение типа `float` хранится как 64-битное двоичное число двойной точности по стандарту <span class="definition__term">IEEE 754</span>. Под значащие цифры отведено 53 двоичных разряда — это примерно 15–17 десятичных цифр. Разрядов конечное число, поэтому точно хранятся не все числа.

</div>

### Аналогия: 1/3 в десятичной записи
{: .block-title}

Число 1/3 нельзя точно записать десятичной дробью: 0,3; 0,33; 0,333; … — сколько цифр ни пиши, точного значения не будет. Если места только на 16 цифр, придётся остановиться и записать приближение.

С двоичной записью то же самое, только «неудобными» оказываются другие числа. Например, 1/10 в двоичной системе — бесконечная периодическая дробь 0,0001100110011…<sub>2</sub>. Места есть только под 53 разряда, и в памяти хранится ближайшее к 0,1 двоичное число, а не само 0,1.

- Большинство десятичных дробей (0,1; 0,2; 0,3; 1,45) в двоичном формате **не представимы точно**.
- Точно представимы дроби со знаменателем — степенью двойки: 0,5; 0,25; 0,125; 0,375.
- При выводе Python показывает самую короткую десятичную запись, которая однозначно указывает на хранимое число. Поэтому `print(0.1)` пишет `0.1`, хотя в памяти не ровно 0,1.
- Это свойство формата, а не Python: то же самое происходит в C, Java, Fortran, R и в электронных таблицах.
- Целые числа `int` Python хранит точно, и арифметика с ними точна.

<article class="example" markdown="1">

```python
print(Decimal(0.5))
```

```text

0.1000000000000000055511151231257827021181583404541015625

```
{: .output}

{: .analysis__title}

- Строка 4: `Decimal(0.1)` переводит хранимое двоичное значение в десятичную запись без потерь. Видно, что в памяти чуть больше 0,1.
- Строка 5: 0,5 = 1/2 хранится точно.

## <span class="subsection__num">2.</span> Одинаковые с виду выражения
{: .subsection__title}

При сложении и умножении приближённых значений погрешности иногда компенсируются, а иногда накапливаются и становятся видны в выводе.

<article class="example" markdown="1">

### Пример 2. Где хвост виден, а где нет
{: .example__title}

Файл `same_looking.py`:

```python
print(0.1 + 0.1)
print(0.2 + 0.2)
print(2 * 0.1)
print(0.2 + 0.1)
print(3 * 0.1)
print(0.1 + 0.2 == 0.3)
print(1 / 3)
```

```text
0.2
0.4
0.2
0.30000000000000004
0.30000000000000004
False
0.3333333333333333
```
{: .output}

<div class="analysis" markdown="1">

Разбор
{: .analysis__title}

- Строки 1–3: погрешности слагаемых совпали с погрешностью хранимого результата, и вывод выглядит «правильно».
- Строки 4–5: результат оказался соседним двоичным числом, а не тем, что хранится для литерала `0.3`. Его кратчайшая запись — `0.30000000000000004`.
- Строка 6: поэтому сравнение `==` даёт `False`.
- Выражения `2 * 0.1` и `3 * 0.1` отличаются одной цифрой, а ведут себя по-разному. Выучить список «опасных» выражений невозможно — нужно другое правило работы.
- Строка 7: бесконечная дробь 1/3 показана с 16 цифрами — так в формат помещается приближение.

</div>

</article>

<section class="subsection" id="s3" markdown="1">

## <span class="subsection__num">3.</span> Не сравнивайте `float` через `==`
{: .subsection__title}

Сравнение вещественных чисел на равенство ненадёжно по трём причинам.

1. Ожидаемое значение обычно записано с меньшим числом цифр, чем результат вычисления.
1. Даже перестановка множителей меняет последнюю цифру результата.
1. Округление не спасает: округлённые значения — тоже приближения.

<article class="example" markdown="1">

### Пример 4. Три причины в одной программе
{: .example__title}

Файл `not_equal.py`:

```python
print(5 / 3)
print(5 / 3 == 1.667)
print(5 / 3 * 0.1)
print(0.1 * 5 / 3)
print(5 / 3 * 0.1 == 0.1 * 5 / 3)
print(round(0.1, 1) + round(0.1, 1) + round(0.1, 1) == round(0.3, 1))
```

```text
1.6666666666666667
False
0.16666666666666669
0.16666666666666666
False
False
```
{: .output}

<div class="analysis" markdown="1">

Разбор
{: .analysis__title}

- Строки 1–2: 1.667 — лишь запись с тремя знаками; до вычисленного значения ей далеко.
- Строки 3–5: математически оба выражения равны 1/6, но разный порядок операций дал разные приближения — они отличаются в последней цифре.
- Строка 6: пример из документации Python. Каждое `round(0.1, 1)` — снова приближение к 0,1, сумма трёх таких приближений — `0.30000000000000004`, а `round(0.3, 1)` — хранимое 0,3.

</div>

</article>

## <span class="subsection__num">4.</span> Три инструмента под три ситуации
{: .subsection__title}

| Ситуация | Инструмент | Как |
|---|---|---|
| сравнить два вычисленных числа | сравнение с допуском | `math.isclose(a, b)` |
| показать число человеку | округление при выводе | `round(x, 2)` или f-строка `f'{x:0.2f}'` ([task 1-7](task_1-7.html)) |
| нужен точный десятичный результат | класс `Decimal` | `Decimal('1.45')` (раздел 5) |
| отфильтровать по порогу | сравнение «больше/меньше» | `gc > 0.4`, `gc < 0.6` |

### Сравнение с допуском: `math.isclose()`
{: .block-title}

<div class="syntax">math.isclose(a, b, rel_tol=1e-09, abs_tol=0.0)</div>

Функция из модуля `math` (task 1-1) возвращает `True`, если числа `a` и `b` достаточно близки. Близость задаётся двумя допусками:

- `rel_tol` — <dfn>относительный допуск</dfn>: доля от большего по модулю из двух чисел. По умолчанию `1e-09`, то есть числа должны совпадать примерно в девяти значащих цифрах. `rel_tol=0.05` — это допуск 5 %.
- `abs_tol` — <dfn>абсолютный допуск</dfn>: разница, которая считается несущественной сама по себе. По умолчанию `0.0`.
- Числа считаются близкими, если разница между ними не больше хотя бы одного из двух допусков.

Если допуски не указаны, используются значения по умолчанию. Чтобы задать допуск, его пишут в скобках после чисел по имени: `rel_tol=0.05`. Такая запись называется <dfn>именованным аргументом</dfn>; подробно — в теме 7 «Функции и декомпозиция программы».

<article class="example" markdown="1">

### Пример 5. Сравнение с допуском
{: .example__title}

Файл `isclose.py`:

```python
import math

print(math.isclose(0.1 + 0.2, 0.3))
print(math.isclose(5 / 3 * 0.1, 0.1 * 5 / 3))
print(math.isclose(1.667, 5 / 3))
print(math.isclose(1.667, 5 / 3, rel_tol=0.001))
print(math.isclose(100, 104, rel_tol=0.05))
print(math.isclose(100, 106, rel_tol=0.05))
```

```text
True
True
False
True
True
False
```
{: .output}

<div class="analysis" markdown="1">

Разбор
{: .analysis__title}

- Строки 3–4: числа, различающиеся только погрешностью формата, признаны равными при допуске по умолчанию.
- Строка 5: 1.667 и 1,66666… отличаются примерно на 0,02 % — это больше допуска по умолчанию.
- Строка 6: с допуском 0,1 % (`rel_tol=0.001`) они уже близки.
- Строки 7–8: при допуске 5 % от 104 разница 4 допустима (4 ≤ 5,2), а разница 6 от 106 — нет (6 &gt; 5,3).

</div>

</article>

### Сравнение с нулём — особый случай
{: .block-title}

Относительный допуск считается от большего из двух чисел. Если одно из них ноль, допуск считается от второго, очень маленького числа, и оказывается ещё меньше. Поэтому `math.isclose(x, 0.0)` без `abs_tol` даёт `False` для **любого ненулевого** `x`. Для сравнения с нулём задают абсолютный допуск.

<article class="example" markdown="1">

### Пример 6. Почти ноль
{: .example__title}

Файл `near_zero.py`:

```python
import math

residual = 0.1 + 0.2 - 0.3
print(residual)
print(math.isclose(residual, 0.0))
print(math.isclose(residual, 0.0, abs_tol=1e-9))
print(math.isclose(0.0, 0.0))
```

```text
5.551115123125783e-17
False
True
True
```
{: .output}

<div class="analysis" markdown="1">

Разбор
{: .analysis__title}

- Строка 4: «остаток» 0,1 + 0,2 − 0,3 — это не ноль, а примерно 5,6 · 10<sup>−17</sup>, погрешность формата.
- Строка 5: без абсолютного допуска такое число не считается близким к нулю.
- Строка 6: с `abs_tol=1e-9` любое число по модулю не больше 10<sup>−9</sup> считается нулём.
- Строка 7: точный ноль равен нулю и без допусков. Это важно для GC-состава: он может быть ровно нулевым.

</div>

</article>

### Сравнение с порогом
{: .block-title}

Если задача звучит «GC-состав больше 40 %», сравнение с допуском не нужно: используйте `>`, `<`, `>=`, `<=`. Погрешность формата может сыграть роль, только когда значение практически совпадает с порогом.

- Строка 7: сравнение с записанным в отчёте значением 0.4333 через `==` — `False`.

### Округление: `round()`
{: .block-title}

<div class="syntax">round(x)       → целое число типа int<br/>round(x, n)    → число с n знаками после точки, тип float</div>

- При точной половине `round()` округляет к **ближайшему чётному**: `round(2.5)` → `2`, `round(3.5)` → `4`. Это <dfn>банковское округление</dfn>: оно не завышает суммы при многократном округлении.
- Число, которое выглядит как половина, может храниться чуть меньше или чуть больше половины. `2.675` хранится как 2,67499999…, поэтому `round(2.675, 2)` → `2.67`.
- Отрицательное `n` округляет до десятков, сотен и т. д.: `round(1234.5678, -2)` → `1200.0`.
- Округляйте **только при выводе**. Округлённое значение не делает дальнейшие сравнения надёжными (пример 4).

<section class="subsection" id="s5" markdown="1">

## <span class="subsection__num">5.</span> Точный десятичный результат: `Decimal`
{: .subsection__title}

Класс `Decimal` из модуля `decimal` стандартной библиотеки хранит числа в **десятичной** системе. Десятичные дроби вроде 0,1 в нём представимы точно, поэтому сложение и умножение таких чисел дают точный десятичный результат. Платой за это служит скорость: вычисления с `Decimal` медленнее, чем с `float`. Поэтому его используют, когда точность десятичных дробей принципиальна: денежные расчёты, дозировки, сравнение с нормативами.

<div class="syntax">from decimal import Decimal<br/>Decimal('1.45')</div>

- Подключение — формой `from … import …` (task 1-1).
- Число создают **из строки**: `Decimal('1.45')`. Если создать его из `float` — `Decimal(1.45)`, — он унаследует неточность исходного числа (пример 1).
- `Decimal` складывается, вычитается и умножается с `Decimal` и с `int`. Смешивать `Decimal` и `float` в одной операции нельзя — возникает `TypeError`.
- `print()` выводит `Decimal` с тем числом знаков, которое получилось в расчёте: `Decimal('2.50') * 3` → `7.50`.

<article class="example" markdown="1">

### Пример 9. Точная десятичная арифметика
{: .example__title}

Файл `decimal_demo.py`:

```python

print(Decimal('0.1') + Decimal('0.2') == Decimal('0.3'))
print(Decimal('1.45'))
print(Decimal(1.45))
print(Decimal('2.50') * 3)
print(type(Decimal('0.1')))
```

```text
0.3
True
1.45
1.4499999999999999555910790149937383830547332763671875
7.50
<class 'decimal.Decimal'>
```
{: .output}

<div class="analysis" markdown="1">

Разбор
{: .analysis__title}

- Строки 5–6: из строки получено ровно 1,45; из `float` — хранимое приближение, чуть меньше 1,45.

<div class="mistake" markdown="1">

Типичная ошибка: `Decimal` вместе с `float`
{: .mistake__title}

Файл `decimal_mix.py`:


```text
TypeError: unsupported operand type(s) for +: 'decimal.Decimal' and 'float'
```

```python
from decimal import Decimal
```
