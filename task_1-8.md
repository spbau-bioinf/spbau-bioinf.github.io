<section class="theory" markdown="1">

## Теоретические сведения
{: .section__title}

Биоинформатика работает с последовательностями нуклеотидов и аминокислот, их идентификаторами и описаниями, а также с величинами, которые по ним вычисляются: длиной, GC-составом, признаком корректности. Прежде чем обрабатывать такие данные, нужно решить, **каким типом Python** представить каждую величину. От этого выбора зависит, какие операции будут доступны и какие ошибки возможны.

Специального «биологического» типа в Python нет — и он не нужен. Последовательность — это строка, длина — целое число, доля — вещественное, ответ «да/нет» — логическое значение, отсутствующее значение — `None`. На этой странице знания из task 1-3 — task 1-7 применяются к данным сквозного проекта семестра «Анализ биологических последовательностей».

</section>

## <span class="subsection__num">1.</span> Что чем становится
{: .subsection__title}

| Биологические данные | Тип Python | Пример |
|---|---|---|
| нуклеотидная последовательность | `str` | `'ATGACCATGATTACG'` |
| белковая последовательность | `str` | `'MTMIT'` |
| идентификатор записи | `str` | `'seq_42'` |
| описание записи | `str` | `'фрагмент гена lacZ'` |

Раз последовательность — строка, к ней применимо всё, что умеют строки: `len()`, склейка, повторение (task 1-4), а после темы 2 — индексация, срезы и методы строк.

### Алфавит последовательности
{: .block-title}

- **ДНК:** A, T, C, G — аденин, тимин, цитозин, гуанин. В РНК вместо T — U (урацил).
- **Строчные буквы** (`acgt`) во многих геномных файлах обозначают <dfn>мягко замаскированные</dfn> участки — например, повторы. Для Python `'atg'` и `'ATG'` — разные строки (task 1-4).
- **N** — любое основание (нуклеотид не определён).
- Есть и другие <dfn>вырожденные коды IUPAC</dfn>, обозначающие один из нескольких нуклеотидов:

- **Белки** записываются однобуквенными кодами 20 аминокислот (M — метионин, K — лизин и т. д.); символ `*` часто обозначает стоп-кодон.

## <span class="subsection__num">2.</span> Что каким типом
{: .subsection__title}

| Величина | Тип | Почему |
|---|---|---|
| идентификатор записи | `str` | текст, а не число, даже если состоит из цифр |
| последовательность | `str` | последовательность символов |
| длина последовательности | `int` | считаем штуки |
| число кодонов, проб, прочтений | `int` | считаем штуки |
| GC-состав | `float` | доля, а не целое |
| «Последовательность корректна?» | `bool` | два исхода |
| описание отсутствует | `None` | не пустая строка, а «ничего нет» |
| код образца с нулями в начале, например `007` | `str` | нули значимы; число `007` Python не примет (task 1-4) |

<aside class="callout callout--important" markdown="1">

Длина всегда целая
{: .callout__title}

Если длина, число кодонов или число проб получились с точкой, значит, где-то в расчёте затесалось деление `/` вместо `//` (task 1-5).

</aside>

<article class="example" markdown="1">

### Пример 2. Число кодонов не того типа
{: .example__title}

### Пустое описание и отсутствующее описание
{: .block-title}

Пустая строка `''` означает «описание есть, но в нём ничего не написано». `None` означает «описания нет вовсе». Проверка `is None` их различает, а проверка истинности `bool()` — нет (task 1-3, task 1-4).

<article class="example" markdown="1">

{: .example__title}

```python

print(empty_description is None)
print(no_description is None)
print(bool(empty_description))
print(bool(no_description))
print(f'Описание: [{empty_description}]')
print(f'Описание: [{no_description}]')
```

```text

True
False
False
Описание: []
Описание: [None]
```
{: .output}

<div class="analysis" markdown="1">

Разбор
{: .analysis__title}

- Строки 3–4: `is None` отличает пустую строку от отсутствующего значения.

## <span class="subsection__num">3.</span> Одна запись FASTA — несколько разнотипных величин
{: .subsection__title}

<dfn>FASTA</dfn> — самый распространённый текстовый формат для хранения последовательностей. Файл FASTA состоит из записей; каждая запись — это строка-заголовок и одна или несколько строк последовательности.

```text
>gene_00284728 length=62;type=dna
GAGAACTGATTCTGTTACCGCAGGGCATTC
GGATGTGCTAAGGTAGTAATCCATTATAAGTA
```
{: .output .output--file data-label="Содержимое файла example.fasta"}

| Часть записи | Где находится | Тип | В примере |
|---|---|---|---|
| признак заголовка | первый символ строки — `>` | — | `>` |
| идентификатор | после `>` до первого пробела | `str` | `gene_00284728` |
| описание | после первого пробела до конца строки; может отсутствовать | `str` или `None` | `length=62;type=dna` |
| последовательность | все строки после заголовка до следующего `>` или конца файла, склеенные вместе | `str` | 62 нуклеотида в двух строках |

По записи вычисляют: длину → `int`, GC-состав → `float`.

<aside class="callout callout--warning" markdown="1">

Формат сложился стихийно
{: .callout__title}

Единой строгой спецификации идентификатора нет; распространённое соглашение — делить строку заголовка по первому пробелу. Типичные ошибки в файлах: лишний пробел сразу после `>` (тогда «идентификатор» оказывается пустым), одинаковые идентификаторы у разных записей, пустые строки внутри последовательности.

</aside>

Читать файлы и разбирать строки программой вы научитесь в темах 2, 8 и 9. Пока части записи переносятся в переменные вручную, а многострочная последовательность собирается склейкой.

<article class="example" markdown="1">

### Пример 4. Запись FASTA в программе
{: .example__title}

Файл `fasta_model.py`:

```python
# Запись из файла example.fasta, перенесённая в программу вручную
record_id = 'gene_00284728'
description = 'length=62;type=dna'
line_1 = 'GAGAACTGATTCTGTTACCGCAGGGCATTC'
line_2 = 'GGATGTGCTAAGGTAGTAATCCATTATAAGTA'
sequence = line_1 + line_2
print('Идентификатор:', record_id)
print('Описание:', description)
print('Длина:', len(sequence))
print('Длина совпадает с описанием:', len(sequence) == 62)
print(f'>{record_id} {description}')
print(sequence)
```

```text
Идентификатор: gene_00284728
Описание: length=62;type=dna
Длина: 62
Длина совпадает с описанием: True
>gene_00284728 length=62;type=dna
GAGAACTGATTCTGTTACCGCAGGGCATTCGGATGTGCTAAGGTAGTAATCCATTATAAGTA
```
{: .output}

<div class="analysis" markdown="1">

Разбор
{: .analysis__title}

- Строки последовательности в файле — лишь способ записи: разбиение на строки не несёт смысла. Поэтому они склеиваются в одну строку.
- Проверка длины сравнивает фактическую длину с числом из описания.
- Две последние строки собирают запись обратно в формате FASTA: знак `>`, идентификатор, пробел, описание — f-строкой; затем последовательность (в одну строку — это допустимо).

</div>

</article>

## <span class="subsection__num">4.</span> GC-состав — обычное вещественное число
{: .subsection__title}

<div class="definition" markdown="1">

<span class="definition__term">GC-состав</span> — доля гуанина и цитозина среди всех нуклеотидных остатков последовательности; обычно выражается в процентах. GC-состав = (число G + число C) / длина.

</div>

Раз это доля, значит `float`, а значит, действуют все правила task 1-6:

- **сравнивать с конкретным значением** — с допуском: `math.isclose(gc, 0.5)`;
- **округлять** — только при выводе: `f'{gc:0.3f}'`;
- **фильтровать по порогу** — через `>` и `<`, а не через `==`;
- **осторожно с нулём**: GC-состав может быть равен нулю, а `math.isclose(gc, 0.0)` без `abs_tol` даст `False` для любого ненулевого, даже крошечного значения.

Подсчитывать буквы G и C в последовательности программой вы научитесь в теме 4 «Циклы и итеративная обработка данных» — так, как требует алгоритм из task 1-0. Пока числа G и C известны заранее (например, их выдал прибор или посчитал лаборант).

<article class="example" markdown="1">

### Пример 5. GC-состав записи
{: .example__title}

В последовательности 14 нуклеотидов G и 8 нуклеотидов C. Файл `gc_record.py`:

```python
import math

sequence = 'ATGGCCATTGTAATGGGCCGCTGAAAGGGTGCCCGATAG'
g_count = 14
c_count = 8
gc = (g_count + c_count) / len(sequence)
print(f'Длина: {len(sequence)} нт')
print(f'GC-состав: {gc:0.3f}')
print('Выше 0.4:', gc > 0.4)
print('Ниже 0.6:', gc < 0.6)
print('Около 0.56:', math.isclose(gc, 0.56, rel_tol=0.01))
print('Ровно 0.5:', math.isclose(gc, 0.5))
```

```text
Длина: 39 нт
GC-состав: 0.564
Выше 0.4: True
Ниже 0.6: True
Около 0.56: True
Ровно 0.5: False
```
{: .output}

<div class="analysis" markdown="1">

Разбор
{: .analysis__title}

- Сумма G и C взята в скобки: иначе на длину делилось бы только число C (task 1-5).
- 22 / 39 = 0,5641…; в выводе — три знака.
- Пороговые проверки не требуют допуска; сравнение с конкретным значением 0.56 — с допуском 1 %.

</div>

</article>

## <span class="subsection__num">5.</span> Одна последовательность и набор последовательностей
{: .subsection__title}

| Признак | Одна последовательность | Набор последовательностей |
|---|---|---|
| тип | `str` | `list` (список, task 1-3) |
| изменяемость | неизменяема | изменяем |
| два имени у одного объекта | безопасно | источник тихих ошибок |

Риск определяется не тем, что данные биологические, а только изменяемостью контейнера. Если передать набор последовательностей в функцию, она получит ссылку на тот же список, а не копию, и её изменения увидит вызывающий код. Подробно — тема 5 «Списки и кортежи» и тема 7 «Функции и декомпозиция программы».

<article class="example" markdown="1">

### Пример 7. Строка против списка
{: .example__title}

Файл `one_and_many.py`:

```python
sequence = 'ATG'

print(same_sequence)

```

ATG
['ATGCC', 'GGTTA', 'CCGTA']

<div class="analysis" markdown="1">

{: .analysis__title}

- Строки 1–5: склейка создала новую строку, и перепривязано только имя `sequence`. Второе имя по-прежнему указывает на `'ATG'`.
- Строки 6–10: `selected` — второе имя того же списка. Добавление «в отобранные» изменило исходную партию: именно так «тихо» портятся данные.
- Элементы списка — строки; при выводе списка они показываются в кавычках, как в интерактивном режиме (task 1-4).
