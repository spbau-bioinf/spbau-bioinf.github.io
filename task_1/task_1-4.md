<section class="theory" markdown="1">

## Теоретические сведения
{: .section__title}

В task 1-3 вы узнали, что каждое значение — объект определённого типа. Теперь разберём четыре встроенных типа, с которых начинается любая программа: целые числа `int`, вещественные числа `float`, логические значения `bool` и строки `str`.

Тип определяет, какие операции со значением допустимы и что они означают. Один и тот же знак `+` складывает числа и склеивает строки. Python никогда не угадывает, что вы имели в виду: текст `'37'` для него не число, пока вы явно не преобразуете его. Это особенно важно для биологических данных, которые приходят в программу из файлов и с клавиатуры в виде текста.

## <span class="subsection__num">1.</span> Целые числа: `int`
{: .subsection__title}

<div class="definition" markdown="1">

<span class="definition__term">int</span> (integer) — тип целых чисел: положительных, отрицательных и нуля. Размер целого числа в Python ограничен только объёмом памяти: результат не «переполняется», даже если в нём десятки цифр.

</div>

### Одно число — четыре записи
{: .block-title}

| Запись | Система счисления | Признак |
|---|---|---|
| `42` | десятичная | обычная запись; не может начинаться с нуля (кроме самого числа 0) |
| `0b101010` | двоичная | приставка `0b` |
| `0o52` | восьмеричная | приставка `0o` (ноль и буква o) |
| `0x2a` | шестнадцатеричная | приставка `0x`; цифры 10–15 записываются буквами a–f |

- Форма записи — свойство текста программы, а не числа. Основание в самом значении не сохраняется: `print()` всегда покажет обычное десятичное число.
- Для удобства чтения цифры можно разделять подчёркиванием: `123_456_789` — то же самое, что `123456789`.
- Знак минус пишется перед числом: `-17`.

<article class="example" markdown="1">

### Пример 1. Записи целых чисел
{: .example__title}

Файл `ints.py`:

```python
print(42)
print(0b101010)
print(0o52)
print(0x2a)
print(123_456_789)
print(-17)
print(9999999999 * 9999999999)
print(type(0x2a))
```

```text
42
42
42
42
123456789
-17
99999999980000000001
<class 'int'>
```
{: .output}

<div class="analysis" markdown="1">

Разбор
{: .analysis__title}

- Строки 1–4 записывают одно и то же число 42 в четырёх системах счисления. Вывод во всех случаях десятичный.
- Строка 5: подчёркивания нужны только человеку; в выводе их нет.
- Строка 7: произведение — двадцатизначное число, и оно получено точно. Целые числа в Python не ограничены по размеру.
- Строка 8: число, записанное в шестнадцатеричной форме, всё равно имеет тип `int`.

</div>

</article>

<div class="mistake" markdown="1">

Типичная ошибка: запятая как разделитель разрядов
{: .mistake__title}

Файл `comma.py`:

```python
print(1,000,000)
print(0,5)
```
{: .code-block--bad}

```text
1 0 0
0 5
```
{: .output}

Ошибки нет — и это хуже, чем ошибка. Запятая в Python разделяет значения: в первой строке `print()` получил три числа `1`, `000` (то есть 0) и `000` и вывел их через пробел. Во второй — два числа, 0 и 5, а не одну половину. Разряды разделяют подчёркиванием (`1_000_000`), дробную часть — точкой (`0.5`). Как `print()` выводит несколько значений, разбирается в [task 1-7](task_1-7.html).

</div>

<div class="mistake" markdown="1">

Типичная ошибка: ноль в начале числа
{: .mistake__title}

Номер образца «007» записан как число. Файл `sample.py`:

```python
sample_number = 007
```
{: .code-block--bad}

```text
  File "C:\Users\student\Desktop\python_work\sample.py", line 1
    sample_number = 007
                    ^^
SyntaxError: leading zeros in decimal integer literals are not permitted; use an 0o prefix for octal integers
```
{: .output .output--error}

```python
sample_number = 7
sample_code = '007'
```
{: .code-block--good}

Сообщение: «нули в начале десятичного числа не допускаются; для восьмеричной записи используйте приставку 0o». Если нули в начале важны (это код образца, а не количество), значение хранят строкой: `'007'`.

</div>

## <span class="subsection__num">2.</span> Вещественные числа: `float`
{: .subsection__title}

<div class="definition" markdown="1">

<span class="definition__term">float</span> (floating point, «плавающая точка») — тип вещественных чисел, то есть чисел с дробной частью. Дробная часть отделяется **точкой**: `4.2`, `3.0`, `-0.5`.

</div>

- Число с точкой — всегда `float`, даже если дробная часть нулевая: `3.0` — вещественное, `3` — целое.
- <dfn>Экспоненциальная запись</dfn>: `2.5e6` означает 2,5 · 10<sup>6</sup>, `1e-09` — 1 · 10<sup>−9</sup>. Буква `e` (или `E`) читается как «умножить на 10 в степени». Такая запись всегда даёт `float`.
- Очень маленькие (меньше 0,0001) и очень большие (от 10<sup>16</sup>) значения `print()` сам показывает в экспоненциальной форме.
- Деление знаком `/` всегда даёт `float`, даже если делится нацело.
- Вещественные числа хранятся с ограниченной точностью, поэтому результаты вычислений с ними бывают приближёнными. Это отдельная большая тема — [task 1-6](task_1-6.html).

<article class="example" markdown="1">

### Пример 2. Записи вещественных чисел
{: .example__title}

Файл `floats.py`:

```python
print(4.2)
print(type(4.2))
print(3.0)
print(2.5e6)
print(1e-09)
print(0.000015)
print(1e16)
print(6.02e23)
print(10 / 4)
print(type(10 / 5))
```

```text
4.2
<class 'float'>
3.0
2500000.0
1e-09
1.5e-05
1e+16
6.02e+23
2.5
<class 'float'>
```
{: .output}

<div class="analysis" markdown="1">

Разбор
{: .analysis__title}

- Строка 3: `3.0` выводится с точкой — это вещественное число.
- Строка 4: 2,5 · 10<sup>6</sup> = 2 500 000 — не слишком большое число, поэтому выводится в обычной форме, с `.0`.
- Строки 5–6: числа меньше 0,0001 выводятся в экспоненциальной форме, даже если записаны обычным образом: `0.000015` превратилось в `1.5e-05`.
- Строки 7–8: числа от 10<sup>16</sup> — тоже в экспоненциальной форме; знак `+` показывает положительный порядок. `6.02e+23` — число Авогадро.
- Строки 9–10: результат деления — `float`, в том числе 10 / 5 = 2.0.

</div>

</article>

## <span class="subsection__num">3.</span> Строки: `str`
{: .subsection__title}

<div class="definition" markdown="1">

<span class="definition__term">str</span> (string) — тип строк, то есть последовательностей символов: текста, нуклеотидных и белковых последовательностей, идентификаторов. Строка записывается в кавычках.

</div>

- Кавычки одинарные или двойные: `'ATG'` и `"ATG"` — одна и та же строка. Открывающая и закрывающая кавычки должны быть одного вида.
- Если внутри текста нужна одинарная кавычка, строку заключают в двойные: `"5'-конец гена"`.
- Кавычки только прямые. «Ёлочки», “лапки” и обратный апостроф `` ` `` дают `SyntaxError` (task 1-0).
- `''` — пустая строка: в ней нет ни одного символа.
- `17` и `'17'` — разные вещи: число и строка из двух символов.
- `print()` выводит содержимое строки без кавычек. Интерактивный режим, показывая значение выражения, пишет строку в кавычках — чтобы было видно, что это строка.

<div class="overview" markdown="1">

Обзорно
{: .overview__label}

Здесь показаны только три базовые операции со строками. Подробно строки — индексация, срезы, методы, форматирование — изучаются в теме 2 «Строки и текстовые данные».
{: .overview__ref}

| Запись | Результат | Что произошло |
|---|---|---|
| `'ATG' + 'GCC'` | `'ATGGCC'` | <dfn>конкатенация</dfn> — склейка двух строк в новую |
| `'CAG' * 4` | `'CAGCAGCAGCAG'` | повторение строки целое число раз |
| `len('ATGGCC')` | `6` | длина строки — число символов, тип `int` |
| `'100' + '150'` | `'100150'` | склейка, а не сложение: оба операнда — строки |
| `100 + 150` | `250` | сложение: оба операнда — числа |

Смысл знака определяют типы операндов: один и тот же `+` в соседних строках таблицы делает разное. Смешивать строку и число нельзя: `'Hello' + 3`, `'Hello' * 3.0`, `'Hello' / 5` вызывают `TypeError` (раздел 6).

</div>

<article class="example" markdown="1">

### Пример 3. Строки и операции с ними
{: .example__title}

Файл `strings.py`:

```python
print('ATG' + 'GCC')
print('CAG' * 4)
print(len('ATGGCC'))
print(len(''))
print("5'-конец гена")
print('100' + '150')
print(100 + 150)
print(type('ATG'))
```

```text
ATGGCC
CAGCAGCAGCAG
6
0
5'-конец гена
100150
250
<class 'str'>
```
{: .output}

<div class="analysis" markdown="1">

Разбор
{: .analysis__title}

- Строка 1: две строки склеены в новую строку `ATGGCC`; исходные строки не изменились (строки неизменяемы, task 1-3).
- Строка 2: триплет `CAG` повторён 4 раза. Так в программе можно получить тандемный повтор.
- Строки 3–4: `len()` считает символы; у пустой строки длина 0.
- Строка 5: одинарная кавычка внутри текста не мешает, потому что строка ограничена двойными кавычками.
- Строки 6–7: одинаковые цифры, разные типы — и разный смысл `+`.

</div>

</article>

<article class="example" markdown="1">

### Пример 4. Строка в интерактивном режиме
{: .example__title}

>>> @@'ATG' + 'GCC'@@

Разбор
{: .analysis__title}

- Значение выражения интерактивный режим показывает в кавычках: `'ATGGCC'`. По кавычкам сразу видно, что результат — строка.
- `print()` выводит только содержимое, без кавычек.
- Если в строке есть одинарная кавычка, интерактивный режим показывает её в двойных.
- `6` — без кавычек: это число.

</div>

</article>

## <span class="subsection__num">4.</span> Логический тип: `bool`
{: .subsection__title}

<div class="definition" markdown="1">

<span class="definition__term">bool</span> (boolean) — логический тип. У него ровно два значения: `True` (истина) и `False` (ложь). Это не строки: они пишутся без кавычек и обязательно с заглавной буквы.

</div>

<div class="overview" markdown="1">

Обзорно
{: .overview__label}

Операции сравнения, логические операторы и истинность значений подробно изучаются в теме 3 «Логика и ветвления». Здесь — только то, что нужно, чтобы получать логические значения.
{: .overview__ref}

### Сравнения дают `bool`
{: .block-title}

| Запись | Вопрос | Пример |
|---|---|---|
| `a == b` | равны? | `12 == 12.0` → `True` |
| `a != b` | не равны? | `4 != 4` → `False` |
| `a < b`, `a > b` | меньше? больше? | `5 > 3` → `True` |
| `a <= b`, `a >= b` | не больше? не меньше? | `3 >= 3` → `True` |

- Числа разных типов сравниваются по значению: `12 == 12.0` — истина.
- Строки равны, только если совпадают все символы, включая регистр: `'ATG' == 'atg'` — ложь.
- `==` — сравнение, `=` — присваивание (task 1-3). Их легко перепутать.

### Истина, ложь и всё остальное
{: .block-title}

Функция `bool(значение)` отвечает на вопрос, считается ли значение истинным. Правило простое: пустое и нулевое — ложь, всё остальное — истина.

| Считается ложью | Считается истиной |
|---|---|
| `False`, `None` | `True` |
| число `0` и `0.0` | любое ненулевое число, в том числе отрицательное |
| пустая строка `''` | любая непустая строка — даже `'0'` и `'False'` |
| пустой список `[]` | непустой список — даже `[0]` |

</div>

<article class="example" markdown="1">

### Пример 5. Логические значения из сравнений
{: .example__title}

Файл `bools.py`:

```python
print(True)
print(type(False))
print(5 > 3)
print(12 == 12.0)
print('ATG' == 'atg')
print(len('ATGC') != 4)
```

```text
True
<class 'bool'>
True
True
False
False
```
{: .output}

<div class="analysis" markdown="1">

Разбор
{: .analysis__title}

- Строки 1–2: `True` выводится без кавычек, тип `False` — `bool`.
- Строка 4: целое 12 и вещественное 12.0 равны по значению.
- Строка 5: строки различаются регистром букв, поэтому не равны.
- Строка 6: сначала вычисляется `len('ATGC')` → 4, затем сравнение 4 != 4 → ложь.

</div>

</article>

<article class="example" markdown="1">

### Пример 6. Что считается истиной
{: .example__title}

Файл `truth.py`:

```python
print(bool(0))
print(bool(0.0))
print(bool(-3))
print(bool(''))
print(bool('0'))
print(bool('False'))
print(bool([]))
print(bool([0]))
print(bool(None))
```

```text
False
False
True
False
True
True
False
True
False
```
{: .output}

<div class="analysis" markdown="1">

Разбор
{: .analysis__title}

- Ноль любого числового типа — ложь; −3 — ненулевое число, значит истина.
- Пустая строка — ложь. Строки `'0'` и `'False'` непустые (в них 1 и 5 символов), поэтому истинны: `bool()` не читает смысл текста.
- Пустой список — ложь; список с одним элементом `0` непустой — истина.
- `None` — ложь. Но пустая строка и `None` — разные ситуации: «описание пустое» и «описания нет». Проверка истинности их не различает; поэтому отсутствие значения проверяют через `is None` (task 1-3).

</div>

</article>

| Вызов | Результат | Правило |
|---|---|---|
| `int('101')` | `101` | строка из цифр (возможно, со знаком и пробелами по краям) → целое |
| `int('101', 2)` | `5` | второй аргумент — основание системы счисления: строка читается как двоичное число |
| `int(42.9)` | `42` | дробная часть **отбрасывается**, это не округление: `int(-42.9)` → `-42` |
| `float(42)` | `42.0` | целое → вещественное |
| `float('3.5')` | `3.5` | строка с точкой → вещественное; запятая не допускается |
| `str(42)` | `'42'` | любое значение → его текстовая запись |
| `bool(0)` | `False` | по правилу истинности (раздел 4) |

`int()` не принимает строку с точкой: `int('4.2')` — ошибка. Если в строке вещественное число, а нужно целое, преобразуют в два шага: `int(float('4.2'))` → `4`.

## <span class="subsection__num">6.</span> Два разных отказа: `TypeError` и `ValueError`
{: .subsection__title}

| Ситуация | Пример | Результат | Что делать |
|---|---|---|---|
| всё сходится | `int('126') / 3` | `42.0` | продолжать работу |
| тип подходящий, но содержимое негодное | `int('hello')` | `ValueError` | проверять данные до преобразования |
| тип вообще не тот | `'126' / 3` | `TypeError` | преобразовать тип или исправить логику |

<div class="definition" markdown="1">

<span class="definition__term">TypeError</span> — ошибка типа: операция неприменима к значениям таких типов (делить строку на число нельзя в принципе).

</div>

<div class="definition" markdown="1">

<span class="definition__term">ValueError</span> — ошибка значения: тип подходит (функция `int()` принимает строки), но конкретное содержимое преобразовать нельзя (`'hello'` — не запись числа).

</div>

Читайте название ошибки в последней строке сообщения — оно уже ставит диагноз. Как перехватывать такие ошибки, чтобы программа не останавливалась, изучается в теме 9 «Файлы, исключения и сквозной проект семестра».

<div class="analysis" markdown="1">

Разбор
{: .analysis__title}

- `invalid literal for int() with base 10: 'hello'` — «неверная запись числа для int() по основанию 10». В конце сообщения показано само негодное значение.
- В Python 3.11–3.12 строка-маркер под кодом выглядит иначе: `^^^^^^^^^^^^` под всем вызовом `int('hello')`. Последняя строка сообщения во всех версиях одинакова.

</div>

</article>

### Пример 10. Не тот тип
{: .example__title}

Файл `bad_type.py`:

```python
print('126' / 3)
```
{: .code-block--bad}

```text
Traceback (most recent call last):
  File "C:\Users\student\Desktop\python_work\bad_type.py", line 1, in <module>
    print('126' / 3)
          ~~~~~~^~~
TypeError: unsupported operand type(s) for /: 'str' and 'int'
```
{: .output .output--error}

<div class="analysis" markdown="1">

Разбор
{: .analysis__title}

- `unsupported operand type(s) for /: 'str' and 'int'` — «операция / не поддерживается для типов str и int». Сообщение называет операцию и типы обоих операндов.
- Знак `^` стоит под операцией, `~` — под её операндами.
- Исправление — преобразовать строку в число: `int('126') / 3` (пример 8).

</div>

</article>

### Частые сообщения
{: .block-title}

| Код | Последняя строка сообщения | Причина |
|---|---|---|
| `'Длина: ' + 150` | `TypeError: can only concatenate str (not "int") to str` | к строке можно приклеить только строку |
| `'CAG' * 3.0` | `TypeError: can't multiply sequence by non-int of type 'float'` | строку повторяют только целое число раз |
| `len(150)` | `TypeError: object of type 'int' has no len()` | длина есть у строк и списков, но не у чисел |
| `int('4.2')` | `ValueError: invalid literal for int() with base 10: '4.2'` | в записи целого числа не может быть точки |
| `int('150 нт')` | `ValueError: invalid literal for int() with base 10: '150 нт'` | в строке кроме цифр есть другие символы |
| `int('')` | `ValueError: invalid literal for int() with base 10: ''` | пустая строка — не число |
| `float('4,2')` | `ValueError: could not convert string to float: '4,2'` | дробная часть отделяется точкой, а не запятой |

## Итоговое задание: карточка последовательности <span class="level level--5">Уровень 5 · итоговое</span>

Файл: <span class="task__file">task\_1-4\_card.py</span>

**Исходные данные** переписаны из журнала секвенирования и хранятся строками:

- идентификатор записи: `seq_17`;
- последовательность прочитана двумя частями: `ATGCGG` и `CCTTAA`; полная последовательность — их склейка;
- длина по журналу: `'12'`;
- число нуклеотидов G и C, подсчитанное лаборантом: `'6'`;
- в соседнем участке — повтор триплета `CAG`, число копий по журналу: `'4'`;
- доля GC = (число G и C) / (длина последовательности).

Напишите программу, которая выводит ровно следующее:

```text
Последовательность:
ATGCGGCCTTAA
Длина по журналу совпадает с фактической:
True
Доля GC:
0.5
Повторяющийся участок:
CAGCAGCAGCAG
Запись для отчёта:
seq_17: 12 нт
```
{: .output data-label="Требуемый вывод"}

**Требования:**

1. Все исходные данные привязаны к переменным с понятными именами в начале программы; числа из журнала хранятся строками, как указано.
1. В коде после исходных данных нет готовых чисел и готовых результатов: всё получается склейкой, повторением, `len()`, преобразованием типов, сравнением и делением.
1. Длину для доли GC и для отчёта берите у фактической последовательности, а не из журнала.
1. Последняя строка собирается склейкой из идентификатора, текста и длины последовательности.
1. В конце файла ответьте комментарием: где в программе потребовалось преобразование типа и какая ошибка возникла бы без него.
