<section class="theory" markdown="1">

## Теоретические сведения
{: .section__title}

Программу можно набрать хоть в «Блокноте», но работать так тяжело: опечатки не видны, табуляции и пробелы неотличимы, строки уползают за край экрана. Поэтому программисты пишут код в <dfn>интегрированной среде разработки</dfn> — редакторе, который подсвечивает код, следит за оформлением и умеет запускать программу.

Большинство программ вы будете запускать прямо из редактора. Но редактор при этом всего лишь вводит за вас команду в <dfn>терминал</dfn>. Когда работа усложнится — появятся входные файлы, параметры запуска, удалённые серверы, — запускать программы придётся из командной строки самостоятельно. Для этого нужно понимать главное: терминал всегда «находится» в какой-то папке, и команда запуска ищет файл именно там.

</section>

<section class="subsection" id="s1" markdown="1">

## <span class="subsection__num">1.</span> Интегрированная среда разработки
{: .subsection__title}

<div class="definition" markdown="1">

<span class="definition__term">Интегрированная среда разработки</span> (IDE, Integrated Development Environment) — программа, которая объединяет редактор кода, запуск программ, встроенный терминал и средства поиска ошибок.

</div>

### Зачем редактор, если хватает «Блокнота»
{: .block-title}

| Проблема | Чем помогает редактор кода |
|---|---|
| опечатка в имени функции | <dfn>подсветка синтаксиса</dfn>: `print`, текст в кавычках, числа и комментарии окрашены по-разному, а имя с опечаткой не окрашивается или подчёркивается |
| смешаны табуляции и пробелы | клавиша <kbd>Tab</kbd> вставляет 4 пробела; сами пробелы и табуляции невидимы, и ошибки от их смешения искать мучительно |
| строка уползла за край экрана | вертикальная <dfn>линейка</dfn> на 79-м символе показывает предел длины строки по PEP 8 (task 1-1) |
| незакрытая скобка или кавычка | парные скобки подсвечиваются, ошибки записи подчёркиваются ещё до запуска |
| нужно запустить программу | кнопка запуска и встроенный терминал в том же окне |

В курсе используется один из двух редакторов: **VS Code** (Visual Studio Code) или **PyCharm Community**. Выбор на оценку не влияет. Названия пунктов меню ниже приведены для английского интерфейса; в новых версиях они могут немного отличаться.

<article class="example" markdown="1">

### Пример 1. Что видно благодаря подсветке
{: .example__title}

Так примерно выглядят две строки в редакторе: встроенная функция выделена цветом, текст в кавычках — другим.

```python
print('Образец принят')  # сообщение для лаборанта
```
{: .code-block--good data-label="Правильное имя: выделено как встроенная функция"}

```python
pirnt('Образец принят')  # сообщение для лаборанта
```
{: .code-block--bad data-label="Опечатка: имя не выделено"}

<div class="analysis" markdown="1">

Разбор
{: .analysis__title}

- Редактор знает имена встроенных функций и выделяет их. Имя `pirnt` ему не известно, поэтому оно остаётся обычного цвета, а многие редакторы ещё и подчёркивают его волнистой линией.
- Такую ошибку видно до запуска программы. Без подсветки вы узнали бы о ней только из сообщения `NameError` (task 1-0).

</div>

</article>

### Настройка VS Code
{: .block-title}

1. Откройте панель расширений (**View → Extensions**, <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>X</kbd>), найдите расширение **Python** от Microsoft и установите его. Без него кнопки запуска Python-файлов не будет.
1. Откройте рабочую папку: **File → Open Folder**.
1. Выберите интерпретатор: <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>P</kbd> → команда **Python: Select Interpreter** → Python 3.11 или новее. Именно этим интерпретатором будут запускаться программы.
1. Откройте файл настроек: <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>P</kbd> → **Preferences: Open User Settings (JSON)**. Добавьте внутрь фигурных скобок четыре строки из фрагмента ниже (если в файле уже есть другие настройки, отделите их запятыми) и сохраните файл.
{: .steps}

```json
{
    "editor.tabSize": 4,
    "editor.insertSpaces": true,
    "editor.rulers": [79],
    "files.encoding": "utf8"
}
```
{: data-label="Фрагмент файла настроек VS Code"}

- `editor.tabSize` — ширина отступа: 4 позиции;
- `editor.insertSpaces` — клавиша <kbd>Tab</kbd> вставляет пробелы, а не символ табуляции;
- `editor.rulers` — вертикальная линейка на 79-м символе;
- `files.encoding` — новые файлы сохраняются в кодировке UTF-8.

Эти же настройки можно задать и без файла: **File → Preferences → Settings**, затем найти в поиске `Tab Size`, `Insert Spaces`, `Rulers`, `Encoding`.

### Настройка PyCharm Community
{: .block-title}

1. Интерпретатор: **File → Settings → Project → Python Interpreter** (в macOS — **PyCharm → Settings**) → Python 3.11 или новее.
1. Отступы: **Settings → Editor → Code Style → Python**, вкладка **Tabs and Indents**: *Tab size* = 4, *Indent* = 4, флажок *Use tab character* снят.
1. Линейка: там же, вкладка **Wrapping and Braces**, поле *Visual guides* = 79.
1. Кодировка: **Settings → Editor → File Encodings**, *Project Encoding* = UTF-8.
{: .steps}

### Как проверить настройки
{: .block-title}

В строке состояния внизу окна редактора при открытом файле `.py` должны быть видны: `Spaces: 4` (в PyCharm — `4 spaces`), `UTF-8` и версия выбранного интерпретатора. В поле текста должна быть видна вертикальная линия справа.

<section class="subsection" id="s2" markdown="1">

## <span class="subsection__num">2.</span> Из чего сделан файл программы
{: .subsection__title}

- Файл программы — **обычный текст**. Его можно открыть любым текстовым редактором; ничего, кроме набранных символов, в нём нет.
- Имя файла заканчивается на **`.py`**: по расширению редактор и система понимают, что это программа на Python.
- Текст хранится в кодировке **UTF-8**. В ней можно записать любые символы Unicode: кириллицу, °, µ, ², — внутри текста в кавычках и в комментариях.
- **Комментарий** начинается со знака `#` и продолжается до конца строки. Интерпретатор его пропускает.
- **Пустые строки** интерпретатор тоже пропускает; они нужны людям, чтобы разделять части программы.

<article class="example" markdown="1">

### Пример 2. Устройство файла
{: .example__title}

Файл `dilution.py`:

```python
# Концентрация ДНК после разведения пробы
# Автор: Иванов И. И., 2026

print('Концентрация после разведения, нг/мкл:')
print(48 / 4)  # проба разведена буфером в 4 раза
```

```text
Концентрация после разведения, нг/мкл:
12.0
```
{: .output}

<div class="analysis" markdown="1">

Разбор
{: .analysis__title}

- Строки 1–2 — <dfn>комментарий-заголовок</dfn>: что делает программа и кто её написал. Интерпретатор их пропускает.
- Строка 3 пустая — она отделяет заголовок от кода и тоже пропускается.
- Строка 4 выводит текст на русском языке: кириллица в файле допустима, потому что он сохранён в UTF-8.
- Строка 5 содержит код и <dfn>комментарий в конце строки</dfn>. Python вычисляет `48 / 4`, выводит `12.0`, а всё после `#` пропускает. Комментарий отделён от кода двумя пробелами (PEP 8, task 1-1).

</div>

</article>

### Комментарий объясняет «зачем», а не «что»
{: .block-title}

Что делает строка кода, видно из самого кода. Комментарий полезен, когда сообщает то, чего в коде нет: смысл действия, происхождение чисел, единицы измерения.

<article class="example" markdown="1">

### Пример 3. Бесполезный и полезный комментарий
{: .example__title}

```python
print(48 / 4)  # делим 48 на 4
```
{: .code-block--bad data-label="Бесполезный комментарий"}

```python
print(48 / 4)  # проба разведена буфером в 4 раза
```
{: .code-block--good data-label="Полезный комментарий"}

<div class="analysis" markdown="1">

Разбор
{: .analysis__title}

- Обе строки выводят `12.0`: для интерпретатора комментарий ничего не значит.
- Первый комментарий повторяет код словами и ничего не добавляет.
- Второй объясняет, откуда взялось число 4. Читатель через месяц — в том числе вы сами — поймёт, зачем здесь деление.

</div>

</article>

### Закомментировать строку
{: .block-title}

Если строку программы нужно временно отключить, не удаляя её, перед ней ставят `#`. Строка превращается в комментарий и не выполняется. В VS Code и PyCharm это делает сочетание <kbd>Ctrl</kbd>+<kbd>/</kbd> (в macOS — <kbd>Cmd</kbd>+<kbd>/</kbd>); повторное нажатие возвращает строку.

<article class="example" markdown="1">

### Пример 4. Отключённая строка
{: .example__title}

Файл `commented.py`:

```python
print('Начало анализа')
# print('Промежуточная проверка')
print('Анализ завершён')  # итоговое сообщение
```

```text
Начало анализа
Анализ завершён
```
{: .output}

<div class="analysis" markdown="1">

Разбор
{: .analysis__title}

- Строка 2 начинается с `#`, поэтому целиком стала комментарием: вызова `print()` в ней для интерпретатора нет.
- Так удобно отключать отладочный вывод: строку легко вернуть, убрав `#`.

</div>

</article>

### Кодировка файла
{: .block-title}

Python ожидает, что файл программы сохранён в UTF-8. Если файл с кириллицей сохранён в другой кодировке (в Windows это часто Windows-1251), интерпретатор отказывается его читать ещё до запуска.

<article class="example" markdown="1">

### Пример 5. Файл не в UTF-8
{: .example__title}

Файл `cp1251_file.py` содержит одну строку `print('Привет')`, но сохранён в кодировке Windows-1251. Запуск в Linux:

```text
SyntaxError: Non-UTF-8 code starting with '\xcf' in file /home/student/Desktop/python_work/cp1251_file.py on line 1, but no encoding declared; see https://peps.python.org/pep-0263/ for details
```
{: .output .output--error data-label="Вывод терминала (Python 3.11–3.13)"}

<div class="analysis" markdown="1">

Разбор
{: .analysis__title}

- `Non-UTF-8 code starting with '\xcf'` — «код не в UTF-8, начиная с байта `\xcf`»: так в Windows-1251 записана буква «П». `no encoding declared` — «кодировка не объявлена».
- Это `SyntaxError`: ни одна строка не выполнена. В Python 3.14 перед этой строкой дополнительно показываются имя файла, номер и текст строки.
- Исправление — пересохранить файл в UTF-8. В VS Code: щёлкнуть по названию кодировки в строке состояния → **Save with Encoding** → **UTF-8**. В PyCharm: щёлкнуть по названию кодировки в строке состояния → **UTF-8** → **Convert**.
- Сообщение упоминает объявление кодировки в первой строке файла: такой способ существует, но в курсе он не нужен — все файлы сохраняются в UTF-8. Подробно о кодировках — в теме 2 «Строки и текстовые данные».

</div>

</article>

<section class="subsection" id="s3" markdown="1">

## <span class="subsection__num">3.</span> Командная строка: где «находится» терминал
{: .subsection__title}

<div class="definition" markdown="1">

<span class="definition__term">Текущая папка</span> (рабочий каталог) — папка, в которой в данный момент «находится» терминал. Команды, которым указано только имя файла, ищут этот файл в текущей папке.

</div>

Текущая папка обычно видна в <dfn>приглашении</dfn> — тексте перед курсором, после которого вводится команда:

- Windows, PowerShell: `PS C:\Users\student>`
- Windows, командная строка cmd: `C:\Users\student>`
- macOS: `student@mac ~ %` (знак `~` обозначает домашнюю папку)
- Linux: `student@pc:~$`

Встроенный терминал VS Code в Windows по умолчанию — PowerShell. Сразу после открытия терминал обычно находится в домашней папке пользователя; терминал VS Code — в открытой в редакторе папке.

### Пути к файлам и папкам
{: .block-title}

- <dfn>Абсолютный путь</dfn> начинается от корня диска и не зависит от текущей папки: `C:\Users\student\Desktop\python_work` (Windows), `/home/student/Desktop/python_work` (Linux), `/Users/student/Desktop/python_work` (macOS).
- <dfn>Относительный путь</dfn> отсчитывается от текущей папки: `python_work\hello_world.py` означает «файл `hello_world.py` в папке `python_work`, которая лежит в текущей папке». Две точки `..` означают папку уровнем выше.
- В Windows части пути разделяются обратной косой чертой `\`, в macOS и Linux — прямой `/`. PowerShell понимает оба варианта.
- Если в пути есть пробелы, путь заключают в кавычки: `cd "Мои документы"`.
- Набирать длинные имена не нужно: введите первые буквы и нажмите <kbd>Tab</kbd> — терминал допишет имя.
- В cmd для перехода на другой диск добавляют ключ: `cd /d D:\work`; в PowerShell достаточно `cd D:\work`.

<aside class="callout callout--warning" markdown="1">

Где на самом деле рабочий стол
{: .callout__title}

Если в Windows включена синхронизация с OneDrive, рабочий стол и «Документы» лежат не в `C:\Users\student\Desktop`, а в `C:\Users\student\OneDrive\Desktop` (или в папке с русским названием «Рабочий стол»). Если команда `cd Desktop` не срабатывает, выполните `dir` и посмотрите, какие папки есть на самом деле.

</aside>

### Пример 6. Перемещение по папкам в Linux
{: .example__title}

Команды, набранные человеком, выделены.

```text
student@pc:~$ @@pwd@@
/home/student
student@pc:~$ @@cd Desktop/python_work@@
student@pc:~/Desktop/python_work$ @@pwd@@
/home/student/Desktop/python_work
student@pc:~/Desktop/python_work$ @@ls@@
hello_world.py
student@pc:~/Desktop/python_work$ @@cd ..@@
student@pc:~/Desktop$
```
{: .output data-label="Терминал Linux (пример; имена папок у вас свои)"}

<div class="analysis" markdown="1">

Разбор
{: .analysis__title}

- `pwd` (print working directory) выводит абсолютный путь текущей папки: терминал стартовал в домашней папке `/home/student`.
- `cd Desktop/python_work` переходит сразу на два уровня вниз по относительному пути. Приглашение изменилось и показывает новую текущую папку.
- `ls` показывает содержимое текущей папки: в ней один файл.
- `cd ..` поднимает на уровень выше — в `Desktop`.

</div>

</article>

<section class="subsection" id="s4" markdown="1">

## <span class="subsection__num">4.</span> Запуск программы из командной строки
{: .subsection__title}

<div class="syntax">Windows:        python имя_файла.py<br/>macOS / Linux:  python3 имя_файла.py</div>

Интерпретатор ищет указанный файл относительно текущей папки. Вместо одного имени можно указать относительный или абсолютный путь к файлу.

### Три шага до запуска
{: .block-title}

| Шаг | Windows | macOS, Linux |
|---|---|---|
| 1\. Перейти в папку с файлом | `cd Desktop\python_work` | `cd Desktop/python_work` |
| 2\. Убедиться, что файл там | `dir` | `ls` |
| 3\. Запустить программу | `python hello_world.py` | `python3 hello_world.py` |

<article class="example" markdown="1">

### Пример 8. Полный цикл запуска
{: .example__title}

Файл `hello_world.py` содержит одну строку `print('Hello, Python world!')`.

```text
student@pc:~$ @@cd Desktop/python_work@@
student@pc:~/Desktop/python_work$ @@ls@@
hello_world.py
student@pc:~/Desktop/python_work$ @@python3 hello_world.py@@
Hello, Python world!
student@pc:~/Desktop/python_work$
```
{: .output data-label="Терминал Linux (пример)"}

<div class="analysis" markdown="1">

Разбор
{: .analysis__title}

- После `ls` мы уверены, что файл находится в текущей папке.
- `python3 hello_world.py` запускает интерпретатор и передаёт ему имя файла. Интерпретатор находит файл в текущей папке, разбирает и выполняет его (task 1-0).
- Программа вывела строку и завершилась, после чего терминал снова показал приглашение: он ждёт следующей команды.

</div>

</article>

<article class="example" markdown="1">

### Пример 9. Запуск не из той папки
{: .example__title}

```text
student@pc:~$ @@python3 hello_world.py@@
python3: can't open file '/home/student/hello_world.py': [Errno 2] No such file or directory
```
{: .output .output--error data-label="Терминал Linux"}

<div class="analysis" markdown="1">

Разбор
{: .analysis__title}

- Терминал находится в домашней папке `/home/student`, и интерпретатор искал файл именно там: полный путь показан в сообщении.
- `can't open file … No such file or directory` — «не могу открыть файл … нет такого файла или папки». Это не ошибка в программе: до её разбора дело не дошло.
- Такое сообщение почти всегда означает, что пропущен шаг 1. Исправление — перейти в папку с файлом или указать путь к файлу.
- В Windows сообщение устроено так же. В его начале может стоять полный путь к `python.exe`, а обратные косые черты в пути к файлу показываются удвоенными: `'C:\\Users\\student\\hello_world.py'`.

</div>

</article>

<article class="example" markdown="1">

### Пример 10. Запуск по пути
{: .example__title}

```text
student@pc:~/Desktop$ @@python3 python_work/hello_world.py@@
Hello, Python world!
student@pc:~/Desktop$ @@python3 /home/student/Desktop/python_work/hello_world.py@@
Hello, Python world!
```
{: .output data-label="Терминал Linux (пример)"}

<div class="analysis" markdown="1">

Разбор
{: .analysis__title}

- Первая команда указывает относительный путь от текущей папки `Desktop`: зайти в `python_work` и взять там файл.
- Вторая команда указывает абсолютный путь; она сработает из любой текущей папки.
- Именно так запускает программы редактор: VS Code вводит в терминал команду вида `& C:/Users/student/…/python.exe c:/Users/student/Desktop/python_work/hello_world.py` — полный путь к интерпретатору и полный путь к файлу. Знак `&` в начале — оператор вызова PowerShell: он сообщает, что дальше записан путь к запускаемой программе.

</div>

</article>

<article class="example" markdown="1">

### Пример 11. Пробел в имени файла
{: .example__title}

В папке лежит файл `my report.py` с одной строкой `print('Отчёт готов')`.

```text
student@pc:~/Desktop/python_work$ @@python3 my report.py@@
python3: can't open file '/home/student/Desktop/python_work/my': [Errno 2] No such file or directory
student@pc:~/Desktop/python_work$ @@python3 "my report.py"@@
Отчёт готов
```
{: .output .output--error data-label="Терминал Linux"}

<div class="analysis" markdown="1">

Разбор
{: .analysis__title}

- Терминал разделяет команду на части по пробелам. В первой команде интерпретатор получил имя файла `my`, а `report.py` — как отдельное, лишнее значение. Файла `my` нет.
- Кавычки объединяют имя с пробелом в одно целое, и запуск проходит.
- Проще всего не использовать пробелы в именах файлов и папок вовсе.

</div>

</article>

<div class="mistake" markdown="1">

Типичная ошибка: команда запуска в интерактивном режиме
{: .mistake__title}

```text
>>> @@python hello_world.py@@
  File "<stdin>", line 1
    python hello_world.py
           ^^^^^^^^^^^
SyntaxError: invalid syntax
```
{: .output .output--error data-label="Интерактивный режим — неверно (Python 3.11–3.12)"}

Команда `python hello_world.py` вводится в терминал, а не после приглашения `>>>`. Выйдите из интерактивного режима (`quit()`) и повторите команду. В Python 3.13 и новее вместо `<stdin>` будет указано `<python-input-0>`.

</div>

<div class="overview" markdown="1">

Обзорно
{: .overview__label}

Путь Windows внутри текста программы. Подробно особые сочетания с обратной косой чертой изучаются в теме 2 «Строки и текстовые данные».
{: .overview__ref}

Внутри кавычек в программе обратная косая черта `\` имеет особый смысл: вместе со следующим символом она может означать специальный знак. Поэтому путь Windows, записанный как есть, может вызвать ошибку.

Файл `path_bad.py`:

```python
print('C:\Users\student\Desktop')
```
{: .code-block--bad}

```text
  File "C:\Users\student\Desktop\python_work\path_bad.py", line 1
    print('C:\Users\student\Desktop')
          ^^^^^^^^^^^^^^^^^^^^^^^^^^
SyntaxError: (unicode error) 'unicodeescape' codec can't decode bytes in position 2-3: truncated \UXXXXXXXX escape
```
{: .output .output--error data-label="Вывод терминала (Python 3.12 и новее)"}

Сочетание `\U` Python понял как начало особой записи символа, которая оказалась неполной. В Python 3.11 последняя строка та же, а под строкой кода стоит один знак `^` в её конце.

Решение: **удваивайте** обратную косую черту. Пара `\\` внутри кавычек означает один символ `\`. Файл `path_good.py`:

```python
print('C:\\Users\\student\\Desktop')
print('Desktop/python_work')
```
{: .code-block--good}

```text
C:\Users\student\Desktop
Desktop/python_work
```
{: .output}

Прямая косая черта `/` особого смысла не имеет и выводится как есть.

</div>

</section>

## Итоговое задание: памятка по запуску <span class="level level--5">Уровень 5 · итоговое</span>

Файлы: <span class="task__file">task\_1-2\_launch.py</span> и <span class="task__file">task\_1-2\_launch\_log.txt</span>
{: .task__meta}

**Часть 1. Программа.** Напишите программу-памятку, которая выводит последовательность действий для запуска *самой себя* из терминала на вашем компьютере и сообщает, каким интерпретатором она выполнена.

Пример вывода на компьютере с Linux, где файл лежит в папке `/home/student/Desktop/python_work`:

```text
Памятка: запуск программы из терминала
Шаг 1. Перейти в папку с файлом:
cd /home/student/Desktop/python_work
Шаг 2. Убедиться, что файл на месте:
ls
Шаг 3. Запустить программу:
python3 task_1-2_launch.py
Программа выполнена интерпретатором:
3.12.3 (main, Mar  3 2026, 12:15:18) [GCC 13.3.0]
```
{: .output data-label="Пример вывода (Linux)"}

**Требования к программе:**

1. Первая, вторая, четвёртая, шестая и восьмая строки вывода — ровно такие, как в примере.
1. Третья, пятая и седьмая строки — настоящие команды для вашей системы и абсолютный путь к вашей рабочей папке. Если путь содержит обратную косую черту, в программе она записывается удвоенной, а на экран выводится одинарной (раздел 4).
1. Последняя строка — значение `sys.version` (task 1-1).
1. В начале файла — комментарий-заголовок (назначение, автор, год). Файл оформлен по PEP 8, ни одна строка не заходит за линейку в 79 символов.

**Часть 2. Проверка памятки.** Выполните в терминале три запуска:

<ol type="a">
<li>точно по своей памятке — из папки с файлом;</li>
<li>из папки уровнем выше, указав относительный путь к файлу;</li>
<li>из домашней папки, указав только имя файла.</li>
</ol>

Скопируйте из терминала всё, что относится к этим трём запускам (приглашения, команды и их результаты), в текстовый файл <span class="task__file">task\_1-2\_launch\_log.txt</span>. В конце файла программы ответьте двумя комментариями: почему запуск (б) сработал и почему запуск (в) не сработал.

После переноса файлов в личную папку памятка будет указывать на старую рабочую папку — это нормально: она описывает запуск в момент выполнения задания.
{: .muted}
